# V22 공통 기능 감지 검토

검토일: 2026-09-15. 읽기 전용으로 `site/lib/tool-similarity.ts`, 기존 카탈로그, 새 AI 6개/SaaS 8개 JSON을 비교했다. 현행 `matches` 함수를 그대로 실행한 결과는 `/private/tmp/ais-v22-capability-current-map.json`이다. Site 파일은 수정하지 않았고 사용자 점수나 대체 서비스 점수를 추가하지 않았다.

## 먼저 수정할 오탐

**GPT-6 Astra의 `텍스트·이미지 입력`이 `이미지 생성`으로 감지된다.** 원인은 `/텍스트.*이미지/`가 생성 여부 없이 입력까지 포함하기 때문이다. 모델간 공통 기능 계산에서 입력 모델을 이미지 생성 모델처럼 설명할 수 있다.

이미지 생성 정규식에서 생성 단어를 요구해야 한다. 예: `/이미지(?:·영상)? 생성|텍스트.*이미지.*생성|text.to.image/`. 이는 `이미지 생성`, `이미지 생성·편집`, `이미지 생성·채우기`, `이미지·영상 생성`, `텍스트로 이미지 생성`을 포함하고 `텍스트·이미지 입력`은 제외한다. 일반적인 `이미지` 단어만으로 확장하지 않는다.

Mistral Vibe는 현행 규칙에서 4개 기능 모두 누락되어 추천 결과가 비어 있다. 위 조사/요약/코딩 보완으로 기존 기능 근거가 있는 항목끼리 연결할 수 있다.

## 모델에 필요한 작은 공통 기능 확장

DeepSeek의 4개 기능은 현행 규칙에서 모두 누락된다. 앱과 모델을 분리하는 기존 `kind === 'model'` 경계는 유지하면서 다음 **3개**만 추가하는 것이 적절하다.

| 공통 기능 | 근거가 있는 현행 기능명 | 주의 |
|---|---|---|
| 시각 자료 입력·분석 | GPT `텍스트·이미지 입력`, Gemini `멀티모달 입력`, DeepSeek `시각 입력`, Claude `문서·시각 자료 분석` | 이미지 생성과 별도 기능. 영상·음성 등 모든 입력을 동일 지원한다고 설명하지 않음. 각 기능 조건을 그대로 표시. |
| 구조화된 출력 | Gemini `구조화된 출력·함수 호출`, DeepSeek `JSON 출력·도구 호출` | 일반 문서 출력이나 표 작성으로 확장하지 않음. |
| 도구 호출·활용 | GPT `도구 활용`, Claude `도구를 쓰는 장기 작업`, Gemini `구조화된 출력·함수 호출`, DeepSeek `JSON 출력·도구 호출` | 연결한 도구/실행 환경이 필요하다는 원문 조건 유지. 모든 모델이 같은 도구를 지원한다고 표현하지 않음. |

추론·긴 문맥도 기록은 있으나 이번에는 별도 공통 기능을 더 늘리지 않아도 된다. 모델명이나 요약의 마케팅 문구를 기능 근거로 사용하지 않는다.

## 확장하면 안 되는 경계

- **음성 대화 ≠ 음성 제작 ≠ 팀 회의.** Copilot 음성 대화와 ElevenLabs 음성 합성을 같은 기능으로 강제 연결하지 않는다. Teams의 회의 녹화·대화 기록은 전사 여부가 명확하지 않아 `전사` 단어 없이 전사 기능으로 올리지 않는다.
- **업무 도구 연결 ≠ 업무 자동 실행.** Mistral `업무 도구 연결`과 Miro `양방향 업무 동기화`를 `연동`이라는 단어만으로 워크플로 자동화로 추가하지 않는다. 연결/읽기와 실제 트리거·액션은 다르다.
- **창작 보드 ≠ 프로젝트 관리.** Firefly Boards, 이미지 편집 타임라인, Vibe Code의 작업 계획을 `보드`·`타임라인`·`계획`만으로 프로젝트 관리에 넣지 않는다. 제목의 기능 범위를 확인해야 한다.
- **항목 댓글 ≠ 팀 채널.** monday `업무별 대화`는 업무 항목의 의견 교환이다. Slack 채널 대화와 동급 팀 메신저 기능으로 자동 분류하지 않는다.
- **데이터 관리 ≠ 데이터 분석.** ChatGPT `파일·데이터 분석`을 Airtable의 구조화된 데이터 관리로 분류하지 않는다. Supabase의 데이터베이스와 Airtable의 업무 데이터가 공통 기능을 갖더라도 완전한 대체 서비스라고 표현하지 않는다.
- `workflow`의 현재 라벨 **앱 간 업무 자동화**는 Asana/Trello 내부 규칙까지 잡으므로 **업무 흐름 자동화**가 더 정확하다. 모든 매치에 외부 앱 간 동작이 보장되는 것은 아니다.
- `unknown` 기능과 출처 없는 기능 제외, 앱/모델 분리, 원본 기능 및 조건 표시를 유지한다. 조건부 기능의 공통점은 같은 플랜·가격·한도를 보장하지 않는다.

## 통합 시 확인할 회귀 사례

1. GPT `텍스트·이미지 입력`은 이미지 생성 매치가 없어야 한다.
2. Runway와 Firefly는 이미지 생성·영상 생성 근거가 각각 남아야 한다.
3. Copilot의 생성·편집은 생성과 편집으로 나뉘고 음성 대화는 음성 제작/회의에 들어가지 않아야 한다.
4. Teams와 Slack은 팀 대화/회의 근거로 연결되며 monday 항목 대화는 팀 채널 매치가 없어야 한다.
5. Mistral Vibe는 조사·요약·코딩의 실제 문서화 기능으로 연결되어야 한다.
6. DeepSeek는 모델들과 시각 입력/구조화 출력/도구 활용으로 연결되고 AI 앱은 섞이지 않아야 한다.
7. Airtable 데이터 보기와 Miro 협업 캔버스는 각각 적합한 기능으로 인식하되 Firefly Boards는 업무 관리에 들어가지 않아야 한다.

위 사례는 동의어와 복합 제목의 실제 누락·오탐을 검증하기 위한 것이며 추천 순서나 서비스 품질 점수를 정답으로 고정하지 않는다.
