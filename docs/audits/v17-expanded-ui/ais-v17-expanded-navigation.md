진입: `/my?tab=savings` 상단 **구독 변경 비교**. 기존 구독1개가 선택 가능하며 초기 폼은 새 이름/금액 등 미입력이다. V01 **현재 조건으로 다시 비교**는 저장 조건을 이 폼에 불러오고 현재 계약·결제 원장을 사용하도록 할 뿐 자동 저장하지 않는다. [Savings.tsx:33](/Users/bigmac_moon/dev/ai_score/site/components/Savings.tsx:33).

- 위에서부터 기존 구독, 비교 시작/종료일, 전환일, **새 요금제** 이름/1회금액/통화/주기/첫청구/세금/별도세금. 주기 `개월 간격 지정`에서만 **결제 간격 (개월)**이 나온다.
- details 1 **좌석·사용량·할인·청구 기준일**: 금액 기준·유료 좌석수·과금 방식·기준일·할인 종료 정상가 적용일·정상가. details 바로 아래 **요금 출처·확인한 조건 / 요금 확인일**도 별도 두 필드라 접힌 캡처에서 빼먹지 않는다.

- details 2 **수수료·일할 추가 정산·확인된 환불**: initially 항목0개. **추가 금액 입력**으로 연 UI 행의 대상안(유지/변경), 종류(수수료/일할/환불)를 읽는다. 환불일 때 **이미 기록된 환불** 선택지가 있고 현재9/12 KRW1,000 원장이 있다. 원장 선택 시 통화·금액·예정일·근거·개별 확인 checkbox는 숨고 **원장 환불을 두 안의 실제 기록에 한 번 반영** 안내가 나타난다. 직접 미래 환불은 그 필드와 확인 checkbox가 나온다. 각 **항목 삭제**는 입력행 제거, 저장 결과 삭제와 다르다. 전체 **추가 비용·환불·일할 정산을 확인했습니다** checkbox는 details 밖이다.

- 하단 **날짜별 비용 비교 / 계약·결제 새로 불러오기**, 결과의 두 안·최대 준비금액·issues·겹침 안내·**날짜별 금액 확인**, 마지막 **이 비교 저장** 제목·선택 상태·이유·사용 결과·**조건과 결과 저장**까지가 범위다. 현재 저장 fixture는 불완전 KRW 결과만 제공한다. 완전/미충족/여러통화/기간전준비 결과를 기존에 있다고 주장하지 말고, root가 기존 inventory 범위에서 실제로 열어 본 입력 상태만 별도로 기록한다.
