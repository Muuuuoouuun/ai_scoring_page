## 해상도와 증거 범위

JPEG SOF에서 파일 자체의 크기를 읽어 각 JSON과 대조했다. 최초에는 CSS viewport와 래스터의 불일치를 알리고 정확한 원본 크기 일치 증거 채택을 보류했다. 이후 root가 전체 묶음에서 도구 screenshot이 doc 폭에 맞춰 전체 viewport를 비례 축소하는 일관 패턴을 확인했으며, CSS viewport와 raster를 manifest에서 분리 기록한다고 설명했다. 따라서 다음처럼 **각 크기를 명시한 교차 화면 판독**으로 진행한다.

| 묶음 | 파일 수 | 실제 JPG 래스터 | JSON CSS viewport / doc 폭 | 판독 표현 |
|---|---:|---|---|---|
| new-D-01–03, edit-D-01 | 4 | 1425×891 | 1440×900 / 1425 | 래스터 1425×891에서 검토한 CSS 1440×900 화면 |
| new-M-01–06, edit-M-01 | 7 | 375×812 | 390×844 / 375 | 래스터 375×812에서 검토한 CSS 390×844 화면 |

D의 가로/세로 비율은 약 0.98958/0.99000, M은 약 0.96154/0.96209로 반올림을 포함한 동일 축소 패턴과 일치한다. 이번 11장에서는 한 장만 다른 해상도이거나 모바일 JSON에 데스크톱 레이아웃이 찍힌 예외를 발견하지 않았다. 다만 이는 도구 구현을 독립 확인한 결과는 아니며 native 100% 픽셀 또는 실제 200% 브라우저 zoom 증거가 아니다. Root가 별도로 설명한 v02-history-D의 잘못된 원본은 이번 V03 묶음 밖이므로 여기에서 직접 판정하지 않았다.

모든 JSON URL은 `http://localhost:5173/my?tab=subscription`이다. new-D는 modal clientWidth/scrollWidth **605/605**, new-M은 **336/336**; edit-D는 **620/620**, edit-M은 **351/351**이다. 숫자는 root가 저장한 DOM 측정 JSON이며, 사진에서도 양쪽 입력 테두리·우측 화살표/달력 아이콘이 모달 안에 보이고 내부 가로 스크롤은 보이지 않는다. DOM 목록 `visibleText`에 들어갔다고 화면에서 완전히 보였다고 판단하지 않고 실제 JPG를 우선했다.

## 닫기·저장과 범위 결론

새 폼의 내부 스크롤 JSON은 D: top 0→648→1288, client 810, total 2098; M: 0→608→1215→1823→2431→2795, client 760, total 3555다. 연속 구간이 서로 겹치며 마지막 위치는 바닥에 도달한다. 사진에서도 새 폼 첫 장에 닫기, 마지막 장에 저장이 있으며 중간 스크롤에서 잘린 필드는 앞뒤 장에서 보완된다. 수정 폼은 D/M 모두 전체 높이가 client/total과 같아 닫기·저장을 한 장에서 확인할 수 있다.

따라서 V03의 요청된 화면들은 실제 이미지로 읽었고, 확인한 범위에서 새 모달 가로 넘침·라벨/입력 충돌·숨겨진 저장 버튼은 발견하지 않았다. 남는 제한은 긴 단일행 이름의 끝부분 미판독, 바닥에서 닫기까지 실제 키보드 이동/상단 복귀 미시험, 저장 실행·검증 오류·DB 반영 미시험이다. 폼을 저장하지 않은 것은 parent가 의도한 QA 경계이며 이 이미지 검토에서 저장 성공으로 확대하지 않는다. 회색 안내의 정량 대비나 200% zoom, 다른 V01–V07 화면까지 포함한 3.4.4 전체 PASS는 이 보고서의 판정 대상이 아니다.
