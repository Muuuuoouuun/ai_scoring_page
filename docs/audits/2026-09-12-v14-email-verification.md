## 연결된 동작

이메일을 꺼둔 상태에서도 digest/matched·명명된 시간대·HH:mm을 저장한다. 명시적인 수신 동의와 세 시간 필드 확인이 없는 이전 설정은 보류한다. 저장 요청은 메일을 보내지 않는다. 현재 실제 처리 진입점은 인증된 `/api/notifications` refresh이며, 무방문 예약 실행은 연결되지 않았다.

하루 요약은 지정한 현지 시각 이후 첫 처리에서 유효한 새 후보를 한 통에 모은다. 빈 평가도 날짜 슬롯을 닫고, 이후 새 항목은 다음 날로 남긴다. 조건 알림은 현지 처리 시작 시각 이후 최근24시간 최대3통이며, 항목 수와 통수를 구분한다. 과거 모든 방식의 시도 통수가 조건 모드 상한에 포함된다. daily에는 rolling3을 추가하지 않으며 소비한 날짜의 다음 실제 현지 due 가드를 유지한다. 당일 미소비 설정의 catch-up을 허용하고 누락 날짜별 과거 메일을 재생하지 않는다.

시간대 변환은 명시 Gregorian/latn/h23 Intl parts와 검증한 UTC 역변환을 사용한다. DST gap은 같은 날짜의 첫 유효 분, fold는 이른 인스턴스, 사라진 날짜는 건너뛴다. 소모한 digest 가드는 모드·시각·시간대·동의 변경으로 앞당기지 않는다. 순수 달력 결과가 미래 미소비 슬롯도 반환할 수 있으므로 실제 빈 평가/첫 시도에만 가드를 기록한다.

`email_deliveries`에 정렬된 항목·고정 요청 본문·수신자·제공사 접수 번호와 시도 이력을 저장한다. 개인별 조건부 선점과 설정 revision이 계획·시도·상한을 보호하고, D1.batch의 후속 SQL도 각자 CAS 조건을 확인한다. 같은 묶음은 동일 key/본문으로 최대3회, 첫 시도 후23시간 안에서만 재시도한다. 접수와 받은편지함 도착은 구분한다.

설정 off·설정 삭제·주제 숨김은 같은 transaction에서 대기 취소/불확실 재시도 보류를 반영한다. 진행 중 외부 요청은 회수한다고 표시하지 않는다. 미시도 묶음의 일부 조건이 달라지면 유효한 생존 항목을 즉시 분리해 다시 계획한다. 늦은 실패는 새 접수 사실을 덮지 못하며, 늦은 성공과 접수 DB 쓰기 실패가 겹쳐도 알고 있는 제공사 ID를 같은 요청의 needs_review에 보존한다. 계정 삭제 뒤에는 새 행을 만들지 않는다.

개인 알림 화면은 미연결/수신 off/시간 확인/대기·한도·재시도와 최근 접수 이력을 읽는다. 개인 내보내기·전체 삭제에 새 테이블을 포함하며, 내보내기에 실행 선점 토큰이나 API 키를 넣지 않는다.

## 실제 브라우저 범위

로컬에서 정상 개발 로그인 경로를 통해 설정을 열었다. 이메일 연결이 없는 상태에서 조건 알림/America/New_York/20:15를 저장하고 새로고침 뒤 복원을 확인했다. 첫 실행에서는 type=time의 화면 값만 바뀌고09:00이 저장되는 오류를 재현했다. input 이벤트도 연결한 수정 후20:15가 복원됐다.

Mars/Olympus를 저장하면 한국어 오류가 표시되고 원래 저장값은 보존됐다. ‘설정 다시 불러오기’가 입력값을 복구하지 않는 문제도 실제 재현 후 수정했으며, 오류가 사라지고 저장된 America/New_York가 복원되는 것을 확인했다. invalid HH:mm은 API 시험으로 확인했으며 브라우저에서 모든 잘못된 native time 입력을 재현한 것은 아니다.

실제390×844에서 문서 폭375, 시간 설정 입력3개 폭295/left40으로 가로 넘침이 없었다. full-page 이미지의 실제 래스터 폭375는 스크롤바를 제외한 값이다. 키보드 Tab의 입력 내부 초점과 solid outline을 관찰했으나 전체 native time 하위 필드/확대/화면 읽기 검증으로 확대하지 않는다. 로컬 알림의 ‘이메일 발송 연결 준비 중’, 대기0·빈 상태를 확인했다. QA 중 바꾼 기존 로컬 설정 한 건은 migration 전 백업과 exact payload 조건으로 복원했고, 다른 로컬 기록은 삭제하지 않았다. 임시 탭은 닫고 viewport를 reset했다.

배포 후 기존 실제 계정에서 설정 화면의 digest/Asia/Seoul/09:00 표시, 이메일 미연결·무방문 예약 미연결 안내, 알림 상태의 대기0·빈 상태를 확인했다. 실제 viewport410/문서395였다. 운영 설정을 저장하거나 가짜 이메일·후기·의견을 만들지 않았다. 새 private 테이블 조회가 포함된 알림 상태 화면은 정상이며 콘솔 error0. 배포 확인 뒤 최근10분 Worker errors_only 결과는 events0이다. 정상 전송/실제 받은편지함/무인 실행 증거로 해석하지 않는다.
