## 확인된 개선 이슈

**1. 현실적인 긴 설명에서 이미 있는 후보를 놓친다.** D1·I2·P2·A2는 카탈로그에 초안·수정, 프로토타입, 상태·날짜·캘린더, 폼·트리거·액션 근거가 있는데 모두 0개였다. R1처럼 7개 트리거를 포함하는 긴 질의는 결과가 나와서, 긴 문장 자체가 일률적으로 차단되는 현상은 아니다. 질의를 의미 있는 업무 토큰으로 나누고 현재 feature 근거와 매칭하는 방식이 필요하다. 동일 20개를 기준으로 재평가하되 새로운 문장도 별도 보류 표본으로 추가해야 특정 표현에만 맞추는 것을 피할 수 있다.

**2. 부정어가 제외할 분야를 오히려 올린다.** N1의 `이미지`가 Canva와 Midjourney를, N2의 `코딩`이 Cursor·Copilot을 높인다. C6도 모델 제외를 반영하지 않는다. 제외 조건을 지원하려면 긍정 의도와 제외 대상을 구분해야 하며, 지원하지 않는 단계라면 해석한 조건을 보여주고 명시적인 분야·유형 제외 입력을 제공하는 것이 정직하다. 현재 Recommend에는 Explore와 달리 분야·유형 선택도 없다.

**3. 제품의 무료 플랜과 요청 기능의 무료 이용이 분리되어 있다.** C5에서 Slack의 현재 feature condition은 그룹 허들이 유료라고 명시하지만, 추천 이유는 `생산성 분야에서 팀 커뮤니케이션, 프로젝트 채널에 활용할 수 있습니다. 무료 플랜이 확인되었습니다. 한국어 지원이 확인되었습니다.`로 나온다. [ToolUI.tsx](/Users/bigmac_moon/dev/ai_score/site/components/ToolUI.tsx:10)의 카드 역시 요약·분야·제품 요금만 보여주고 그 기능 조건은 표시하지 않는다. 무료 체크박스 자체는 제품 필터로서 작동하지만, 이 요청에는 조건 충돌 경고나 후보 제외가 필요하다. 공식 요금표도 무료의 일대일 허들과 유료 Pro의 그룹 허들을 구분한다. **4. 통과 사례에도 상위 후보의 근거를 개선할 여지가 있다.** C3는 Gemini가 3위라 고정 최소 기준을 충족하지만, 추천 표면에서 이미지 생성 조건을 명확히 연결하지 않는 Canva·Figma가 먼저 나온다. 현재 카탈로그에 수록되지 않은 기능을 추가로 추정해 이 순위를 정당화하지 않는다. 해당 제품이 실제 이미지 생성을 못 한다는 주장도 아니다. V1의 Vercel은 카탈로그상 배포·운영 근거가 중심이어서 코딩 제안과 같은 직접 업무와 구분이 필요하다. 이러한 부가 관찰로 기존 PASS를 소급 변경하지 않았다.

API 모델 자체를 업무 앱과 동일한 사용 경험으로 가정하지 않았고, 현재 sourceUrl에 없는 오프라인 사용·보안 보장·특정 앱 통합 등의 기능을 기대 기준에 추가하지 않았다. C4의 owned 목록은 실제 사용자의 도구 보유나 권한 상태가 아닌 합성 QA 값이다.

## root가 UI에서 대조할 체크리스트

로컬 함수 결과는 재현했으므로 대체 실행을 요청하는 상황은 아니다. 배포 UI까지 증거를 연결하려면 같은 질의를 입력하고 **출력을 보기 전에 아래 기준을 유지**하면 된다. 이 보고서 작성자는 브라우저를 조작하지 않았다.

1. `/recommend`에서 D1·I2·P2·A2를 각각 입력하고 무료·한국어·내 도구함은 해제한다. 현재 관찰처럼 0개인지, 수정본이라면 각 사전 지정 후보가 상위 3개에 등장하는지 기록한다.
2. N1·N2·C6를 입력하고 추천 6개 전체를 확인한다. 제외한 분야·유형이 다시 들어오는지, 사용자가 제외 조건을 알아볼 수 있는지 기록한다.
3. C5에서 무료·한국어를 체크한다. Slack 노출 여부와 함께 `그룹 허들은 유료`라는 구체적 조건이 추천 카드 또는 인접 경고에 표시되는지 확인한다. 다른 페이지의 상세에만 있는 조건은 이 기준을 충족하지 않는다.
4. C1·C2는 빈 결과가 성공이다. 후보를 만들기 위해 한국어 `확인 필요`나 유료 제품을 조건 충족으로 바꾸지 않는다.
5. C3는 사전 최소 기준을 유지하되 이미지 생성에 대한 실제 근거·한도가 상위 카드와 어떻게 연결되는지 별도로 기록한다. C4는 준비된 QA 계정이 있는 경우에만 실제 도구함 범위와 대조하며 실제 계정 보유 상태를 이번 합성 입력으로 대신하지 않는다.

평가 결과와 실패 원인을 root에게 먼저 전달했으며, 사이트 파일·운영 기록·점수 문서는 수정하지 않았다.
