## 관찰 규격

- **D**: 데스크톱 CSS viewport 1440×900, 100%를 권장. **M**: 모바일 390×844, 100%. 도구가 이 값을 지원하지 않으면 실제 `innerWidth/innerHeight`를 기록한 일관된 대체값을 사용한다. 바깥 앱 창 크기를 내부 사이트 viewport로 기록하지 않는다.
- **Z**: 실제 브라우저 200% 확대에서 각 주 화면을 점검한다. 확대 API/브라우저 기능이 없으면 200%는 미관찰로 남긴다. viewport 축소를 실제 확대라고 부르지 않는다. 좁은 320 CSS px reflow를 추가하면 작은 폰 폭/긴 문자열을 별도로 확인할 수 있다.
- 아래 주 화면 행은 기본적으로 **D/M/Z 모두** 대상. 길면 상단·중간·하단을 보고, 전체 캡처 외에도 글자를 판독할 수 있는 실제 크기 구간을 보관한다. 팝업/서브 상태는 해당 행의 확장 매트릭스를 이어서 관찰한다. 내용만 달라지고 구조가 같은 상태를 중복 캡처할 필요는 없으나 미관찰 변형을 사실대로 남긴다.
- 추가 분기점은 760/761 및 1050/1051 CSS px에서 공통 헤더·카드·상세 2열·마이 메뉴·모달·비교 결과 등 **레이아웃 가족별** 전환을 점검하면 된다. 모든 글/제품에 분기점 조합을 반복할 필요는 없다. 500px 이하의 저장 조건 설명목록도 한 번 확인한다.
- 각 증빙에는 `행 ID / 정확한 URL과 query / 배포·관찰 시각 / guest·owner·admin / 빈 상태·데이터·확장 / 실제 viewport / zoom / 스크린샷 경로 / 측정·비평 / 수정 후 재확인`을 적는다. 현재 버전과 다른 배포의 사진은 구별한다.

## 반드시 펼쳐볼 주요 상태

모달·긴 폼·표·저장 결과는 D/M/Z를 모두 확인한다. 조건 차이만 있는 항목은 한 화면에 여러 조건을 구성하여 검증할 수 있다. 사용자가 직접 입력한 QA 데이터는 **공식 사실/실제 후기와 구분**하며 공개 서비스에 가짜 후기를 게시할 필요가 없다.

## 한 화면 안에서도 확인할 사항

1. 첫 시선에서 페이지 목적·주 작업·현재 선택을 찾는지, 2차 작업(원문·저장·수정·삭제)이 주 작업과 구분되는지. 같은 계열 화면의 제목·간격·버튼·정보 카드가 일관적인지. 화면별 최소 1개 근거 있는 비평을 기록하고 ‘괜찮음’만 반복하지 않는다.
2. 작은 메타데이터/긴 한국어·영문 제품명/통화·날짜/URL/오류가 잘리거나 겹치지 않는지, 필드 레이블·보조 설명·오류가 입력과 함께 보이는지. 대비는 실제 computed 색 및 필요한 측정으로 확인한다. 사진의 인상만으로 수치 합격을 주장하지 않는다.
3. 본문 가로 overflow와 의도한 표/개인 메뉴의 내부 스크롤을 구분한다. 페이지 바깥 가로 스크롤이 없어도 표의 마지막 열·모달 하단이 접근 가능한지 확인한다. focus outline이 sticky header·dock·모달 경계에 가려지는지도 확인한다.
4. 키보드로 헤더→검색/필터→주 작업→footer 이동, 모바일 메뉴, details, 표 스크롤, dialog를 확인한다. 원문 링크나 단순 입력 상태 관찰에 외부 인증·공개 게시·계정 삭제까지 실행할 필요는 없다.
5. 빈/로딩/오류는 서로 다른 상태다. 데이터 없는 관리자나 커뮤니티 화면을 데이터 상태라고 표시하거나 통제 fixture를 운영 데이터라고 표시하지 않는다. 기존 데이터/권한을 확보할 수 없으면 그 칸을 `미관찰(사유)`로 남긴다.

## 소스에서 발견한 시각 관찰 우선 지점

- `MyWorkspace.tsx`의 도구함 빈 안내 조건은 전체 `libs.length===0`이다. 도구가 존재하지만 상태/모음 필터 결과가 0건인 경우에는 안내 없이 목록 영역이 비어 보일 수 있다. **실제 필터 0건 화면을 확인할 우선 후보**이며, 전체 빈 상태와 다르다.
- 마이 메뉴는 모바일에서 가로 스크롤되는 7개 버튼이다. 첫 화면에 없는 알림/설정으로 키보드와 터치 양쪽에서 도달 가능한지 확인한다.
- 긴 기능표·3개 제품 비교·청구 표·관리 표·V9 결과표는 서로 열 수/overflow 처리가 다르므로 같은 ‘표 있음’ 한 건으로 묶지 않는다.
- TermsEditor의 새 조건 + 상세 필드 + 미리보기, V9 추가금액/선결제 조건 + 저장 결과가 가장 긴 상호작용 상태다. 모달 또는 페이지 하단의 제출·취소가 특히 중요하다.
- 소스에는 focus-visible, reduced-motion, native dialog, 작은 화면 입력 글자 크기, 표 스크롤 영역 등이 있다. 이는 구현 인벤토리이며 렌더링/보조기술 실측 증빙을 대신하지 않는다.
