## 화면별 관찰

**30 — 공식 피드.** 선택된 공식 피드 탭과 원문·수집정보 안내, 제품·날짜→제목→갱신정보의 반복 순서는 분명하며 로딩 문구나 가로 잘림은 보이지 않는다. 항목마다 외부 링크 화살표가 제목 아래 독립 줄에 놓인 것으로 보여 긴 목록의 세로 길이를 더 늘리므로, 제목과 같은 줄 끝에 붙이면 훑어보기 밀도를 개선할 여지가 있다. 1425×4912 원본이 도구에서 594×2048로 축소 표시됐으므로 작은 보조 글자의 실제 크기·가독성은 이 축소 보기로 단정하지 않는다.

**31 — 소식 상세.** ChatGPT·공식 출처 표시, 큰 제목, 게시·확인 날짜, 요약, 적용 대상·제공 상태의 순서가 안정적이고 읽기 폭과 문단 간격이 충분하다. 공식 원문 버튼이 저장 버튼보다 강조되어 다음 행동이 명확하며 제목·본문·버튼 잘림이나 로딩 흔적은 보이지 않는다.

**32 — 혜택.** 미국·자격 확인 필요 배지와 혜택 제목, 마감·적용 범위 안내, 참여 자격·이용 조건의 구분이 분명하여 혜택 조건을 먼저 읽게 한다. 단일 혜택에 공간을 충분히 주는 차분한 화면이며 본문 줄바꿈·공식 링크·날짜가 잘리지 않고 로딩 흔적도 보이지 않는다.

**33 — 구독 해지 안내.** 서비스와 실제 결제 경로의 라벨이 두 선택 상자 바로 위에 있고, 확인 필요 상태에서 영수증 확인→결제 경로 확인의 번호 순서를 제시하여 초기 상태를 이해하기 쉽다. 안내와 개인 기록 버튼이 분리되고 주요 문장은 읽기 편하나 아래쪽 보조 주의문은 상대적으로 작고 옅어 중요도에 비해 눈에 덜 들어온다. 선택 상자·행 번호·문장의 잘림이나 미완성 로딩은 보이지 않으며, 이 캡처는 서비스 미선택 상태에 한정된다.

**34 — 출처·갱신 현황.** 제품 이름·로고, 확인 시각, 공식 업데이트·로고 출처, 상태 배지를 같은 카드 구조로 반복하여 상태 비교는 일관되지만 넓은 카드의 빈 공간과 반복 시각 정보로 페이지가 길다. 하단 Supabase·Vercel의 로고 칸은 비어 보이고 갱신 확인 대기가 표시되므로 완전히 채워진 성공 상태의 예시로 보아서는 안 되며, 캡처만으로 원인을 특정할 수 없다. 가로 잘림·로딩 문구는 없지만 1425×3839 원본이 760×2048로 축소 표시되어 보조문 실제 가독성은 확정하지 않는다.

**35 — 커뮤니티.** 제목·안내→필터→글 목록의 순서가 명료하고 파란 글 작성 버튼이 주 행동으로 구분되며, 한 건인 목록에서는 넓은 여백이 생기지만 잘림이나 미완성 로딩은 보이지 않는다. 게시글은 화면 자체에 검증용 기록·실제 제품 평가 아님이라고 명시된 로컬 QA 자료로, 실제 사용자 후기나 배포 커뮤니티 활성도 증거로 해석하지 않는다. 하단 경험·평점 집계 안내는 옅은 보조문이므로 핵심 설명이 필요한 방문자에게는 상대적으로 눈에 덜 띈다.

**37 — 개인정보.** 적용일과 여섯 소제목으로 긴 내용을 나누고 소개 화면과 같은 읽기 폭·서체·여백을 유지하여 문서 간 일관성이 있다. 단락이 길어 개별 사실을 빠르게 찾을 때는 천천히 읽어야 하지만 본문 잘림·과밀·로딩 흔적은 보이지 않으며, 정책 문구의 법적 충분성이나 실제 시스템 동작을 이 이미지로 검증하지는 않는다.
