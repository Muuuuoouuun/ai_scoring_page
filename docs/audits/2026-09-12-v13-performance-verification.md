## 사전 고정 측정 방법

같은 in-app browser와 QA tab13, 같은 로그인 세션에서 홈→탐색을 교대로 각3회 전체 문서 탐색했다. 수정 전6개를 모두 저장한 뒤 소스를 변경했다. 배포 후도 같은 순서6개다. 각 단계의 첫 홈은 setup 탐색 뒤 reload이며 나머지는 navigate다. 초기 setup이나 최종 기능 QA 탐색을 표본에 섞지 않았다.

실제 진단 viewport는12개 모두1280×720, 문서 폭/스크롤 폭1265/1265, 최상위 문서, initial/current visible·visibilityChanges0이다. 최초1440×900 요청은 QA 탭에 적용되지 않았기에 실제1280으로 프로토콜을 정정했고 첫 표본도 보존했다. 로컬 반응형 QA는 별도 탭이다.

기존 진단의 문서 시작10초 목표 자동 JSON을 DOM에서 읽었다. 실제 elapsedMs는10000~10005ms다. 초기 관측기 등록은 늦을 수 있고 지원되는 buffered 항목에 의존한다. 진단 버튼의 상호작용이 LCP를 마감할 수 있다. 네트워크·캐시를 통제하거나 throttle하지 않았다. 단일 브라우저 소규모 문서 실험이며 전체 사용자 p75·냉캐시·비로그인 방문·호스팅 전체 성능·D1 자체 시간을 뜻하지 않는다. 기다림 도구가10초 전에 timeout된 경우 같은 문서의 자동 기록이 끝난 뒤 읽었으며 느린 표본을 버리지 않았다.
