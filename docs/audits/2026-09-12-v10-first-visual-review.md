2026-09-12. 지정된 **01, 02, 04, 05, 06 PNG를 view_image로 직접 열어 읽고 비교**했다. 06은 원본 detail 옵션으로도 다시 열었으나 도구 출력에서 축소 표시됐으므로 작은 글자의 실제 CSS 픽셀 크기를 그 이미지로 측정한 것은 아니다. 03은 hydration 전 입력/결과 불일치로 root가 거절한 캡처이며 열거나 근거로 사용하지 않았다. 수정된 CSS만 읽었고 브라우저·Sites·사이트 파일을 조작하지 않았다.

**판정:** 04에서 긴 검색어의 줄바꿈 복구, 05에서 개요 제목의 헤더 가림 해소를 시각적으로 확인했다. 05의 기능표는 정보가 잘려 있지는 않지만 핵심 설명·조건이 작고 옅어 모바일 기본 크기에서 편하게 비교하기 어렵다. 06의 홈은 성인 업무용 정보 서비스로서 어조와 위계가 안정적이다. 이 다섯 장으로 전체 화면 게이트를 변경하지 않는다.

## 01 → 04: 검색 overflow 수정

- [01 수정 전](/Users/bigmac_moon/dev/ai_score/docs/audits/v10-screens/01-explore-long-query-before-mobile.png): 결과 메타의 긴 영문 검색어가 오른쪽으로 한 줄로 뻗어 페이지를 넓힌다. ‘입력한 목적과의 관련도순 · 평점순 아님’은 오른쪽 끝에서 거의 한 글자씩 세로로 밀렸다. 빈 결과 카드와 footer는 왼쪽 좁은 영역에 남아 화면 전체 구조가 무너진 모습이다.
- [04 수정 후](/Users/bigmac_moon/dev/ai_score/docs/audits/v10-screens/04-explore-long-query-fixed-mobile.png): 긴 영문 검색어가 본문 폭 안에서 여러 줄로 감기고, 정렬 설명이 아래에서 정상적인 한 줄로 읽힌다. 제목→검색/필터→결과 건수/검색어→빈 상태→초기화 행동의 순서가 복구됐다. 화면 오른쪽으로 뻗던 긴 문자열과 세로로 찌그러진 정렬 설명은 보이지 않는다.
- 01과 04는 정확히 동일한 문자열의 픽셀 차이 비교는 아니다. 둘 다 충분히 긴 공백 없는 영문 검색 상태이며, 04의 입력에서 보이는 접두부와 결과에 표시된 접두부는 일치한다. 거절된 03을 성공 증거로 대체하지 않았다.
- CSS의 `.results-meta{flex-wrap:wrap;gap:8px 20px}`와 자식 `min-width:0;overflow-wrap:anywhere`가 이미지에서 보이는 변화와 맞는다.

**관측 한계:** root는 full-page 캡처 도구가 scrollbar 폭 차이로 다시 배치하는 현상을 확인했다. 따라서 04는 캡처 결과에서 줄바꿈/위계 수정이 보인다는 근거다. 이 PNG 하나를 실제 viewport의 clientWidth=scrollWidth 측정으로 취급하지 않는다. 최종 모바일 치수 판정은 root의 viewport 캡처와 실제 DOM 폭 기록에 연결해야 한다.

## 02 → 05: 개요 앵커 가림 수정

- [02 수정 전](/Users/bigmac_moon/dev/ai_score/docs/audits/v10-screens/02-detail-anchor-before-mobile.png): ‘어떤 도구인가요?’ 제목이 고정 헤더 뒤에 들어가 보이지 않고 개요 설명도 상단에서 일부 가려진다. 사용자가 개요로 이동했지만 중간 문장부터 읽게 되는 상태다.
- [05 수정 후](/Users/bigmac_moon/dev/ai_score/docs/audits/v10-screens/05-detail-anchor-fixed-mobile.png): 헤더 아래 분명한 여백 뒤에 ‘어떤 도구인가요?’ 제목과 개요 문단 전체가 나타난다. 개요→업무 태그→‘주요 기능과 조건’의 순서가 분명하다. 상단 여백이 내용을 과도하게 밀어낸다는 느낌도 없다.
- CSS의 `main[id],main section[id],main article[id]{scroll-margin-top:100px}`와 관측된 이동 위치가 맞는다.

**확인 범위:** 이 자료로 확인한 것은 캡처된 **개요 앵커**다. 유사 도구 앵커·행사 앵커·다른 viewport도 완료됐다고 확대하지 않는다. 실제 키보드 조작이나 스크린리더의 읽기 순서를 수행한 것은 아니다.

## 05 모바일 기능표: P2 수준의 가독성 개선 가치

기능명과 지원/조건부 배지는 구분되고 행 사이 여백도 있다. 즉, 정보가 겹치거나 셀이 붕괴한 표는 아니다. 하지만 세 열 중 왼쪽 설명은 좁은 폭에서 짧게 여러 줄로 끊기고, 오른쪽 이용 조건·출처도 작고 옅게 보인다. 상단 14px급 개요 문단을 읽다가 표로 내려오면 핵심 판단 정보가 급격히 작아진다.

실제로 ‘웹 검색’, ‘파일·데이터 분석’, ‘이미지 생성’, ‘Deep Research’와 상태는 읽을 수 있지만, 각 설명과 플랜 조건을 빠르게 훑어 비교하기에는 눈을 더 가까이 대거나 확대하고 싶어지는 밀도다. **“읽을 수 있다”와 “모바일 기본 크기에서 편하다”를 구분하면 후자는 아직 부족하다.** 조건은 부가 장식이 아니라 선택에 필요한 내용이므로 작은 각주처럼 다루기 어렵다.

수정 방향은 조건/기능 설명의 글자 크기와 줄간격을 우선 높이는 것이 적절하다. 현재 모바일 CSS의 10px 설명·11px 셀보다 한 단계 큰 본문 크기로 확인하고, 세 열을 유지해도 줄 수가 늘어나는 것은 허용한다. 표의 출처·제약을 삭제하거나 말줄임으로 감추는 해결은 피한다. root가 글자 크기를 올리는 방향을 적용하겠다고 했으나, 수정 후 새 이미지를 아직 보지 않았으므로 해결 판정은 하지 않는다.

명도 대비를 계산하거나 특정 접근성 수치 기준 실패를 측정한 것이 아니며, 실제 200% zoom 확인도 아니다.

## 06 홈 데스크톱: 성인 어조·밀도·위계

[06 홈 이미지](/Users/bigmac_moon/dev/ai_score/docs/audits/v10-screens/06-home-desktop.png)는 root 설명에 따라 **localhost의 고정 로컬 QA 데이터 화면**이다. 아래 사용 경험 영역의 ‘검증용 후기 — 원문 수정 확인’을 실제 공개 제품 후기나 배포 콘텐츠 결함으로 판단하지 않는다. 배포 홈의 커뮤니티 빈 상태와 이 화면을 구분한다.

좋은 점:

- 옅은 노랑 hero와 파란 CTA가 검색으로 시선을 모으지만 전체 화면은 흰 여백·얇은 구분선·절제된 카드에 머문다. 유아적 장식이나 과도한 축하/판매 문구는 없다.
- ‘일에 맞는 도구를 찾고, 쓰는 방법까지 확인하세요’가 가장 강한 첫 메시지다. 검색 → 공식 업데이트 → 기능별 탐색 → 도구 카드 → 활용법 → 행사/사용 경험으로 내려가는 흐름을 한눈에 읽을 수 있다.
- 큰 제목, 도구 이름, 설명, 보조 메타의 차이가 분명하다. 주된 파란 행동은 찾기이고, 내 도구함은 더 아래의 보조 영역에 있어 정보 탐색이 개인 관리에 밀리지 않는다.
- 3열 × 2행 도구 카드와 아래 가이드 목록이 규칙적으로 정렬되어 있다. 로고의 서로 다른 형태도 카드 안에서 정돈돼 보이며 본문이 혼잡하지 않다.

개선 여지가 있는 부분:

- 카드 하단의 요금 정보와 공식 업데이트의 날짜/서비스 이름은 얇고 작아, 크기가 줄어든 전체 페이지 이미지에서는 확인에 더 집중해야 한다. 직접 화면의 기본 크기에서 읽기 쉬운지는 viewport 캡처로 확인할 가치가 있다. 특히 Figma처럼 두 줄이 되는 요금 설명은 카드 사이 시각적 높이를 비교해 본다.
- 카드 내용의 높이에 비해 내부 여백이 넉넉하고, 카테고리/카드/다음 섹션 사이에도 간격이 크다. 현재는 답답함보다 차분함이 강해서 즉시 압축할 이유는 없다. 홈 전체가 길다고 정보 삭제로 해결할 수준의 과밀 문제는 보이지 않는다.
- 영문 eyebrow는 작은 보조 역할이고 한국어 주제목을 방해하지 않는다. ‘성인 어조’를 위해 친근한 한국어 질문이나 옅은 노랑을 무조건 제거할 필요는 없다.

## 게이트 적용 범위

이번 실제 이미지 검토는 이전 순수 소스 추정보다 강한 근거지만, 홈 데스크톱·탐색 모바일·도구 상세 모바일의 제한된 샘플이다. 고정 게이트 3.1.4의 complete theme, 3.2.4의 every principal screen, 3.4.4의 complete cross-screen 비교를 전부 충족했다고 말하지 않는다. 200%/전체 reflow/실제 screen-reader도 열어 둔다. 신규 PASS·점수 변경 없음.
