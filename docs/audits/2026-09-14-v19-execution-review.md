## 실제 확대 검증

## 관찰 제한과 복구

- 존재하지 않는 데이터 상태(로컬 이력 draft/void·번들, 확정 해지 기존 기록, 운영 실제 사용자 응답·숨긴 알림 등)는 존재하는 것처럼 표시하지 않았다. 모든 가능한 데이터 조합이나 새 계정을 생성하는 검증으로 범위를 늘리지 않았다.
- 로컬 후기에는 업무1개·플랜1개만 있어 UI 선택으로 만들 수 있는 0표본 조합이 없다. 0명/미평가 기본 상태와 실제 존재하는 필터 결과를 별도 연결했다. 오류를 보려고 실제 운영 API를 중단하지 않았다.
- 처음 로딩 중이었던 검색·랭킹·커뮤니티와 출처 첫 카드는 로딩 완료 후 별도 캡처로 보완했다. 인라인 폼을 모달로 잘못 찾은 시도, 화면 밖에서 찍힌 환불 연결 이미지, 알림 표시 전환 중/사라진 뒤 이미지는 성공 증거와 구분했다.
- S08 native select 자체의 닫힌 한 줄 표시를 전체 이름 판독으로 인정하지 않았다. 전체 구독 정보를 별도 표시한 뒤 실제 화면에서 재확인했다.
- 세금 확인 합성 fixture는 기존2행 payload의 정확한3값만 잠시 바꾸고 원문으로 복구했다. 저장 콘텐츠 fixture는 새1행만 추가·제거했으며 정상 UI 저장에서 그 임시 행의 updated_at만 달라졌다. 두 복구 모두 원7행의 모든 열이 원래 백업과 정확히 같은지 확인했다. 커뮤니티나 DB 전체를 과거 백업으로 덮어쓰지 않았다.
- 최종적으로 로컬·배포 도메인의 Chrome 확대율은 모두100%(CSS1920×796, dpr1)로 복원했고 viewport override를 해제했다. 로컬 미리보기 서버와 검증 탭은 정리했다. 배포 사이트의 기존 Codex 탭에 열기 요청을 보냈고 응답은 queued였다.

## 실제 화면 읽기와 목표 제어

VoiceOver는 일반 시작과 설정 화면을 통한 시작을 시도했다. 사용자 Chrome 입력 중단 후에도 설정은 ON이지만 실행 목록에서 VoiceOver가 실행 중이 아니었고, 실제 발화·자막이 관찰되지 않았으며 앱 연결도 시간 초과했다. 설정을 OFF로 복구했다. DOM/접근성 트리/스위치 ON을 실제 읽기 성공으로 대신하지 않으므로 5.2.4는 UNVERIFIED다. 앱 자체의 읽기 결함이 확인됐다고 단정하지 않는다.

사용자는 목표 재개를 요청했고 실제 작업은 계속했다. 그러나 목표 도구에는 기존 목표를 active로 바꾸는 기능이 없고, Codex 앱 자체의 컴퓨터 제어는 명시적으로 허용되지 않았다. 이를 다른 프로세스나 내부 상태 변경으로 우회하지 않았다. 마지막 get_goal은 blocked였으며 목표 전체 달성이나 제어 상태 재개를 주장하지 않는다.

메일 발신 설정·동의된 실제 이메일 수신·무인 실행 일정, 독립적인 실제 배포 계정/기기, 외부 방문자 관찰, 비교 이해 관찰, 실제 전체계정 삭제 흐름은 이번 UI 검증으로 대체되지 않는다. 최종 목표인 모든9영역88 이상은 별도 점수표의 미해결 항목이 남는 동안 미완료다.
