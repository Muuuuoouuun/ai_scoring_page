## 남은 발견 사항

### P2 — 한국어 제외 대상의 왼쪽 경계가 없어 다른 명사의 일부를 분야로 해석

`lib/catalog-search.ts`의 `interpretQuery()` 내 `add()`는 영문/숫자에만 대상 경계를 검사한다. 뒤쪽 허용 조사·수식어 검사가 추가됐지만 한국어 왼쪽 경계는 여전히 없다.

실제 `바코드 도구는 제외하고 문서 작성`의 결과:

- `positive = '바  문서 작성'`
- `exclusions = [{type:'category', value:'development', label:'개발'}]`
- `unresolvedExclusions = []`

카탈로그에 없는 바코드 대상에서 ‘코드’를 잘라 개발 분야를 제외하고, 화면에는 정상 해석된 개발 제외로 나타난다. 불명 대상을 추정하지 않고 미적용 표시한다는 현재 계약에 어긋난다. **같은 정규화·한국어 단어 경계를 제외 후보에도 적용**하고, 허용한 조사/접속어·수식어만 대상으로 인정하는 작은 수정이 필요하다. 특정 `바코드` 문자열을 예외 목록에 넣는 방식은 적절하지 않다.

### P2 — 지원하지 않는 부정 문법이 미적용 안내 없이 긍정 가점에 들어감

현재 marker는 `말고/빼고/제외/원하지 않음/필요 없음` 계열만 감지한다. `아닌/없이`는 marker 자체가 없어 unresolved에도 들어가지 않는다.

| 실제 입력 | 결과 |
|---|---|
| 이미지 생성이 아닌 보고서 작성 | exclusions=[], unresolved=[]; Midjourney 1위. 부정한 이미지 생성이 가장 강한 긍정 의도가 됨 |
| Notion 없이 보고서 작성 | exclusions=[], unresolved=[]; Notion 2위. 제외 미적용 안내 없음 |

모든 자연어 부정을 완벽하게 파싱할 필요는 없지만, **인식 범위 밖의 부정을 아무 제한 없이 긍정 지원으로 사용하는 것은 피해야 한다.** 확실한 제품/분야 대상의 `아닌/없이`를 처리하거나, 적어도 그런 조건을 미적용이라고 알리고 해당 부정 구간을 긍정 가점에서 분리해야 한다. `코딩뿐만 아니라 문서도`, `로그인 없이`, `무료가 아닌`처럼 의미가 다른 형태를 단순히 한 정규식으로 모두 category 제외에 연결하지 않는다. “무료가 아닌”은 최신 보완으로 자동 무료 필터는 해제됐지만 유료만을 요구하는 의미까지 구현됐다고 말하면 안 된다.

### 정밀도 한계 — 행동 단어·입력 대상의 부분 일치를 직접 요청 기능과 구분할 필요

이 항목은 고정 V10 상위3 최소 기준을 소급 실패로 바꾸는 근거가 아니며, 특정 제품을 고정 위치로 옮기라는 뜻도 아니다.

- `보고서 작성`: Midjourney가 4위이고 matched feature는 `텍스트로 이미지 생성` 하나다. description의 ‘프롬프트를 작성해’가 `작성`의 직접/개념 점수를 받는다. 실제 등록된 기능을 그대로 보여주므로 사실을 만들어낸 것은 아니지만, 보고서를 작성하는 기능 근거는 아니다.
- `이미지 생성`: GPT-6 Astra가 4위이고 실제 근거는 `텍스트·이미지 입력`, description은 텍스트 출력이다. 입력 이미지를 이해하는 기능과 이미지 생성 기능이 같은 동작처럼 강하게 연결된다.
- `art`: `hasTerm()`의 3자 이상 부분 문자열 규칙으로 `Artifacts`만 찾아 Claude 한 개를 반환한다. 짧은 제품명 접두 검색과 일반 업무 단어의 부분 일치를 같은 규칙으로 처리하는 한계다.

출력 자체의 조건/원문은 보존돼 있어 신기능을 임의 추가했다고 판정하지 않는다. 개선한다면 업무의 목적어+행동 구문 또는 직접 기능 일치를 우선하고, 보통 행동 단어 하나만 맞는 근거를 ‘관련 기능’의 동일 강도로 설명하지 않는 일반 규칙을 권한다. 현재 실제 제품 ID별 보너스/고정 순위는 코드에서 발견하지 못했다.

## 검토 도중 root가 이미 보완한 사항

최초 읽기에서 아래 세 반례를 root에게 먼저 전달했다. 이후 위 11:47:43Z 실행에서는 다음과 같이 달라져 **최초 결함을 현재 미해결로 중복 보고하지 않는다.**

| 최초 문제 | 최신 보관 실행 |
|---|---|
| `보고서 작성, 광고는 제외하고`가 writing 제외 + positive 빈 값 + 전체 탐색으로 바뀜 | writing을 제외하지 않음. positive에 보고서 작성 유지, unresolved에 광고 표시 |
| `Notion은 제외하지 말고 문서 작성`이 Notion 제외 | exclusions 없음, Notion 결과 유지 |
| `모델을 제외하지 말고 코딩`이 모델 제외 | exclusions 없음, 모델 결과 유지 |
| `무료가 아닌 이미지 생성` / `무료가 아니어도 이미지 생성`에 자동 무료 필터 | 두 입력 모두 meaning.free=false, Midjourney 포함 |
| `그림자는 빼고 보고서 작성`에서 그림 부분으로 image 제외 | 뒤쪽 허용 구문 검증으로 image 제외하지 않고 unresolved로 표시 |

`Notion과 Slack은 제외하고 협업`의 알려진 두 제품 제외도 현재 작동했다. 알려진 대상과 모르는 대상을 섞은 `Notion과 광고를 제외하고 문서 작성`은 전체 해당 구간을 unresolved로 알리고 제외를 적용하지 않는다. 일부만 처리했다고 숨기지 않으므로 현재 보수적 정책과 맞다. 문장부호 없이 불명 제외와 앞 업무가 섞인 경우 앞 업무까지 unresolved로 묶여 0건일 수 있는데, 이는 잘못된 분야 제외보다 보수적이며 안내에 원문을 노출한다.

## 제약·소유권·반환 계약 확인

**28개 교집합 검사와 7개 API 계약 검사에서 회귀를 발견하지 못했다.** 실제 검색 함수를 호출했으며 랭킹 구현을 복사한 테스트는 아니다.

- 4개 입력(빈 질의/코딩/이미지 생성/보고서 작성)에 category, kind, free, korean, owned[], 일부 owned/미등록 ID, 불가능한 category×kind를 조합했다. 결과는 원 결과의 부분집합이며 각 필터를 만족했다. `owned:[]`가 전체 목록으로 완화되지 않았다.
- API에서 `%`, 빈 입력, Notion/type=tool, ChatGPT/all, 전혀 일치하지 않는 업무, 161자, 잘못된 type을 호출했다. 성공 응답의 `results/counts/total/partial`, total과 counts의 합, type 필터를 유지했다. 빈/구두점/불명 업무는 0건, 161자 및 잘못된 type은 400이었다.
- 카탈로그와 options/owned 배열은 검색 전후 동일했다. `Tool + relevance` 배열 반환과 `catalog.ts` wrapper가 유지돼 Explore/Recommend/전체 검색 API/MCP의 기존 `.map/.slice` 호출 형태와 맞는다. 새 모듈의 catalog import는 type-only라 서버 런타임에 React/DOM/네트워크 의존을 추가하지 않는다.
- 전체 검색 API의 published/nonreply SQL, hidden/private 제외, wildcard escape, 커뮤니티 DB 오류 partial 처리 코드는 변경되지 않았다. 이 부분의 모든 기존 API 테스트를 이번 하위 검토가 새로 실행했다고 주장하지 않는다.
- 무료 옵션의 기존 제품 수준 `pricing.includes('무료')`, 한국어의 `=== '지원'`, kind/category 조건은 그대로다. 현재 카탈로그 데이터에서 이 필터를 완화하지 않았다. 다만 미래에 `무료 플랜 없음` 같은 가격 문구가 추가되면 contains 검사는 별도 명시적 상태가 필요하다는 기존 설계 한계는 남는다.

### Recommend의 다중 계정/비동기 도구함 범위

현재 `{owner, ids}` 상태, `userId` 의존 effect의 초기화, cleanup의 `current=false`, 응답 setter의 `current` 검사, 렌더 단계의 `owned.owner === userId` 검사로 이전 계정 응답이 새 계정의 검색 범위로 쓰이는 것을 방어한다. onlyMine에서 조회 중/실패/로그아웃도 결과를 전체 카탈로그로 폴백하지 않는다. `setOnlyMine(false)`를 사용자 선택으로 제공하는 것과 자동 폴백을 구분한다.

이 판단은 **소스의 비동기/소유 ID 경계 검토**다. 실제 두 계정 로그인·네트워크 순서 변경·브라우저 UI 실행은 수행하지 않았으며 실제 다중 계정 검증 완료로 확대하지 않는다.

### 기능 근거와 표시

`matchedFeatures`는 원 feature 객체를 그대로 반환하고 Recommend는 name/status/description/condition/sourceUrl을 읽어 표시한다. 조건부/unknown을 지원으로 표시하지 않고, 무료 제품과 요청 기능의 조건을 나눠 안내한다. Slack 그룹 허들의 유료 조건을 DOM에 노출할 경로가 소스에 존재한다. 실제 화면의 판독·잘림·필터 변경 후 표시 갱신은 root UI 검증 범위다.

## 이번 결과의 한계

기존 8개/추가 테스트의 성공 수는 root의 실행 보고와 소스에서 확인했으며 이 보고서의 28+7 검사는 별도의 제한된 반례·호환성 재현이다. 다른 검토자가 수행 중인 frozen36 평가를 대신하지 않는다. 임시 반례는 설계 검토 후 작성한 회귀 탐색 자료이며 사전에 비공개로 보류한 독립 사용자 표본이 아니다. 소스가 이후 수정되면 위 소스 해시/실행 시각의 판정과 구분해 반례만 다시 확인해야 한다.
