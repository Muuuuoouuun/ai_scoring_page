## API·근거·개인 범위

`searchCatalog`는 기존의 `Tool + relevance` 배열을 유지하고 추가 근거 배열만 제공한다. 실제 순서와 숫자 relevance가 같은 비교식에 따른다. 새로운 타입 import는 런타임에 제거되며 순수 검색 모듈에 React/DOM/외부 요청·개인 데이터 저장을 추가하지 않는다. category/kind/free/korean/owned 조건은 교집합으로 작동하고 owned[]의 0건을 완화하지 않는다. 전체 검색 API의 공개 글 SQL·hidden/private 제외·LIKE escape·부분 오류 처리 코드는 유지된다. 그 전체 기존 API 테스트를 이번 검토가 재실행했다고 주장하지는 않는다.

matchedFeatures의 상태·설명·조건·공식 URL은 원문 그대로다. `requirements/unverifiedRequirements`는 환경·수량 조건을 확인되지 않은 요구로 표시할 뿐, 새 공식 기능을 카탈로그에 추가하지 않는다. Recommend의 원문 조건/출처 및 미확인 요구 표시 경로를 확인했으며 화면 판독은 root 브라우저 검증 범위다.

실제 `Provider`의 공개 user 타입은 **`{name:string} | null`**이다. 현재 Recommend는 그 객체 참조를 owner로 보관하고 effect cleanup/current 검사 및 렌더 시 owner 동일성으로 이전 응답을 현재 범위에 쓰지 않도록 한다. onlyMine의 로딩·실패·로그아웃은 전체 목록으로 자동 폴백하지 않는다. **초기 보고서의 ‘userId 경계’ 설명은 당시 Recommend만 읽고 실제 Provider 타입까지 대조하지 못한 한정 설명이었다. 이번에는 Provider/layout과 현재 객체 참조 방식의 호환성을 확인했으며, 실제 계정 ID가 클라이언트에 있다고 다시 주장하지 않는다.** 이 검사는 현재 Provider 사용자 객체가 바뀌는 전환의 소스 검토이고, 독립적인 실제 두 계정 세션 검증은 아니다.

## 남아 있는 정밀도 한계

- 영문 3자 이상 부분 문자열 규칙은 아직 `art`를 `Artifacts`에 연결한다. 모든 단어 의미가 해석됐다는 주장에는 사용할 수 없다.
- 대상 그룹의 우선순위와 일부 행동 확인은 제한된 규칙이다. 복수 업무, 입력/출력의 모든 방향, 모든 접속·부정 표현을 문법적으로 완전히 해석하는 구조가 아니다. 원문 근거·미적용/미확인 안내와 현재의 비보장 문구를 유지해야 한다.
- 숫자 relevance는 업무 관련도 내부 값이며 실제 품질·사용자 적합 확률이 아니다. frozen36 평가, 실제 추천 UI, 배포 상태, 고정 점수 변화는 각각 별도 증거로 판단한다.
