## 먼저 전달한 실패와 범위 위험

1. **H09 — 팀 채널 목적보다 일반 대화가 앞선다.** `Notion 제외하고 팀 대화를 채널별로 모으고 싶어요`에서 Notion 제외는 유지됐지만, Gemini → GitHub Copilot → Gemini Notebook → Slack 순서로 Slack이 4위라 고정 상위 3개 기준에 실패했다. 상위 후보의 근거는 대화·문서 분석, 코드 대화, 소스 기반 대화이며 팀 채널과는 다른 작업이다.
2. **H14 — 특정 기능 조건 하나를 보여도 네 단계 무료라는 필수 조건 전체는 미확인이다.** Zapier의 `다단계 워크플로` 조건에는 무료 2단계 제한과 공식 URL이 실제 반환되고 현재 렌더링 분기에 연결돼 있다. 이 부분은 통과다. 그러나 Flash, Make, Vercel, Copilot, Figma도 함께 추천되며 이들의 네 단계 무료 처리 여부가 확인되지 않았다는 구체적 안내가 없다. 새 표본은 이 요구를 이미 고정했으므로 사례 전체는 FAIL이다. 일반 무료 플랜 안내와 모든 요구를 보장하지 않는다는 공통 문구로 그 요구를 충족했다고 바꾸지 않았다.
3. **H15 — 오프라인·기기 내 처리 조건을 식별하지 않는다.** `인터넷 연결 없이 기기 안에서만 문서를 요약`에 6개 후보가 나오지만 반환 근거나 캡처한 Recommend/SearchMeaning 코드에서 해당 조건의 확인 필요 안내가 없다. 외부 제품 모두가 이 기능을 못 한다는 주장이 아니라, 이번 추천에서 등록 근거 없는 필수 조건을 구체적으로 알려주지 않는 문제다.
4. **H16 — 미등록 목적에서 예약의 뜻을 혼동한다.** 자전거 수리점 방문 예약 확정 요청에 Make 한 개를 제시하며 근거가 `예약 실행`이다. 그 기능은 정해진 간격의 시나리오 실행이고 방문 시간 예약·확정의 근거가 아니다. 현재 표시 경로는 이 목적이 미등록 또는 확인되지 않았다고 설명하지 않는다.
5. **H11 — 보이는 추천은 통과하지만 전체 결과에는 범위가 남는다.** 코딩 도구를 원하지 않는다는 문장에서 development 분야만 제외한다. 상위 6개에는 고정 제외 ID가 없어 사례는 PASS지만 전체 함수 결과 8위에 productivity 분야의 GPT-6 Astra가 남는다. Explore가 같은 함수 전체를 사용하므로 그 경로의 의미상 제외 위험이다. 표시 최대 6개라는 고정 기준을 관찰 후 확대하여 H11을 FAIL로 바꾸지 않았다.

제품명으로 명시한 Notion·Midjourney·Figma는 해당 질의의 전체 결과에서도 제외됐다. 긍정 경계인 `이미지가 필요해요`를 제외로 해석하지 않았고 H03은 Midjourney·Gemini·ChatGPT로 최소 기준을 충족했다. 이번에 계정 범위를 전체로 넓히는 UI 동작이나 인증 우회를 실행·검증한 것은 아니다.

## 기존 C5 조건 경고 판정의 정확한 근거

기존 기대는 Slack을 제외하거나 무료 그룹 허들 요구와 충돌하는 구체적 조건을 추천 표면에 표시하는 것이었다. 이번에는 실제 Slack의 matchedFeatures에 `허들`, `conditional`, `무료 플랜은 일대일 허들, 그룹 허들은 유료 플랜 기준입니다.`, `https://slack.com/pricing`가 반환됐다. 스냅샷의 Recommend는 `t.matchedFeatures.map`에서 해당 feature의 상태·condition·sourceUrl을 그대로 표시하는 분기를 갖고 있어 **데이터와 렌더링 코드 연결 기준으로 PASS**다. 실제 브라우저에서 그 문구를 봤다는 의미는 아니다.

같은 원칙으로 H14의 Zapier 2단계 제한도 조건 반환·렌더링 연결은 확인했다. 두 사례의 판정 차이는 기존 C5는 Slack의 특정 충돌 표시를 요구하고, 새 H14는 함께 나온 다른 후보들의 네 단계 무료 조건도 확인되지 않았다면 표시하도록 사전에 정했다는 데 있다. 기대를 바꾸거나 한쪽 기준을 다른 쪽에 뒤늦게 적용하지 않았다.

## 한계와 다음 확인

이번 판정은 초기 스냅샷 한 번의 읽기 전용 실행이다. 실제 UI의 줄바꿈·가시성·접근성이나 요청 중 계정 전환 동작은 root의 별도 UI 검증과 연결해야 한다. 추가 구현 후에는 같은 고정 표본을 보존한 채 새 관찰 파일로 실행해야 하며 이 초기 실패 기록을 덮어쓰면 안 된다. 카탈로그에 기록된 공식 출처와 조건을 활용했지만 이번 실행에서 외부 제품 기능을 새로 조사하거나 작업을 수행하지 않았다.
