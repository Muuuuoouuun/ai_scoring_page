# 운영 피드백 설계 — V12

통합 기획 v0.6의 정보 이해와 개인 관리 도움을 각각 관찰하는 요구를 구현한다. 기존 전체 승인/권장 진행을 따른다. 정기 실행은 Sites의 배포 경로와 machine identity가 확인되지 않았고 이메일 공급자도 아직 연결되지 않았다. 해당 전체 범위를 유지하되 이 설계는 독립적으로 필요한 선택적 피드백 기능을 완성한다. 피드백만으로1.2.4/9.4.4 전체 완료 점수를 받지 않는다.

기존 커뮤니티 ‘도움 됐어요’는 공개 글 반응만 다루므로 정보 이해·개인 관리의 분모로 쓸 수 없다. 외부 분석 SDK는 불필요한 방문 추적과 새로운 의존성을 추가한다. 별도 내부 의견 API와 관리자 집계를 사용한다.

화면 하단의 정보 이용 의견, 로그인한 마이페이지의 개인 관리 의견을 사용자가 직접 연다. 자동 팝업이나 기사마다 의무 응답은 없다. 질문은 각각 ‘필요한 정보를 이해하는 데 도움이 됐나요?’, ‘기록·비용·해지 등을 정리하는 데 도움이 됐나요?’다. 도움 됨/일부 도움/도움 안 됨/아직 이용하지 않음/판단 어려움을 분리하고 구체적 의견은 선택 입력이다. 의견은 공개되지 않으며 운영자가 읽는다는 점을 제출 전에 알린다.

같은 탭의 임의 토큰, 서버에서 확인한 계정(비회원은 별도), 질문 영역/버전을 기준으로 한 건을 보관한다. 토큰은 서버에서 해시하며 계정 ID는 클라이언트 입력을 신뢰하지 않는다. 같은 질문을 다시 열어도 시작 수를 늘리지 않고 응답을 수정하면 최신 응답으로 바꾼다. 다른 계정과 영역은 별도 기록이다. 비회원은 현재 탭의 토큰으로만 본인 의견을 수정·삭제할 수 있으며 탭 저장소를 잃으면 복구할 수 없다고 알린다. 로그인 의견은 계정 내보내기·전체 삭제에 포함한다.

의견 창을 연 뒤 서버가 시작 기록을 받으면 시작1건, 응답 저장 시 응답1건이다. 닫거나 중단한 시작은 미응답으로 남는다. ‘아직 이용하지 않음’과 ‘판단 어려움’을 무응답·실패·0점으로 바꾸지 않는다. 관리자 집계는 조회 시점 직전30일(UTC)의 시작 코호트다. 영역별 시작/응답/미응답, 판단 가능한 응답과 도움 됨 비율, 비회원/로그인 응답 경로를 나란히 표시한다. 방문자 수나 고유 인원, 전체 사용자의 만족도, 실제 업무 성과라고 부르지 않는다. 두 영역을 합친 종합 점수는 만들지 않는다.

수집 내용은 질문 버전·영역·페이지 종류(검색어/URL 쿼리/개인 기록 내용 제외)·선택 응답·선택 의견·시각·계정 구분이다. 연락처나 계약 금액 등 민감 내용을 적지 않도록 짧게 안내한다. 운영자가 최근 답변을 볼 수 있고, 사용자는 자신의 해당 의견을 삭제할 수 있다. 보관 기한/정기 삭제를 새로 약속하지 않는다.

오류 시 입력을 유지하고 재시도한다. 시작 요청 응답이 늦어 창을 닫거나 계정이 바뀌어도 다른 컨텍스트의 응답을 폼에 반영하지 않는다. 모달은 기존 초점 복원/가두기/Escape 동작을 재사용한다. 관련없는 페이지·계정 데이터를 자동 수집하지 않는다.

검증은 실제 API/SQLite 마이그레이션으로 비회원/개인 인증 경계, Origin, 반복·수정·취소·다른 계정, 내보내기/삭제, 분모/미시도/미응답과0분모를 확인한다. 로컬 UI에서 두 영역의 저장·재열기·수정·삭제·모바일/키보드를 수행한다. 배포에는 합성 이용 성과를 제출하지 않는다. 배포의 의견 진입과 관리자 빈/기존 상태를 확인하고 실제 사람 응답과 QA를 구분한다.
