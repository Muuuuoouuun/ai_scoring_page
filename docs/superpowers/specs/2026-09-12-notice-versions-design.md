# V15 혜택 조건과 알림 버전

승인 근거: 사용자의 전체 구현·검증·비공개 배포 승인. 원문 2026-09-11 cancellation-promotion-alerts-design.md 74–106행을 구현한다. 새 발송 사업자나 실제 수신 증거를 만들지 않는다.

## 결정

notifications와 email_outbox, email_deliveries는 기존 버전/시도 기록을 보존한다. notification_cards는 한 행사 또는 하나의 공식 발표를 가리키는 안정적인 카드다. 같은 도구의 서로 다른 발표는 별개 카드이며 숨김은 기존 update:tool 범위다. 원본 자료에 명시적인 증가 revision을 두고 notice_source_heads가 더 오래된 실행의 카드/발송 변경을 차단한다. 같은 revision에 다른 중요 사실은 충돌로 보류한다. 확인일, 단순 제목/소개 문구, 배열 순서는 행사 중요 버전에서 제외한다. 가격·갱신·기간·자격·마감·대상 지역·기능 조건·공식 철회 상태는 포함한다. 발표는 명시적인 announcement id로 구분한다.

카드 변경과 새 버전 행·큐는 설정 revision 및 source head, 카드 CAS를 각각 확인한다. 발송 계획/첫 시도/재시도도 모든 항목의 현재 카드와 source head를 확인한다. 기존 provider payload와 idempotency key는 수정하지 않는다. 오래된 시도는 자동 재시도하지 않으며 성공 응답의 단조 기록을 보존한다.

날짜와 정확한 deadline instant는 구분한다. 공식 절대 마감은 그 시각부터 이메일 불가다. 날짜만 있는 마감은 가장 이른 시간대(UTC+14)에서 해당 날짜가 시작하는 시점부터 이메일을 보류하고, 가장 늦은 시간대(UTC−12)에서 그 날짜가 완전히 지난 뒤에만 날짜 경과로 표시한다. 이는 보수적인 내부 발송 정책이며 공식 마감 시각이라고 표시하지 않는다. 정확한 시각이 미확인이어도 먼 미래 날짜의 혜택은 다른 조건이 모두 확인되면 가능하다. 날짜 자체도 불명확하면 보류한다.

자격 확인은 자격 사실 fingerprint에 묶는다. 화면에서 현재 fingerprint를 보고 사용자가 eligible을 명시적으로 선택해야 새 확인을 저장한다. 가격만 변경되면 같은 자격 확인은 유지한다. 이전 eligible 문자열만 있는 자료는 재확인이 필요하다. 열린 이전 폼의 fingerprint 불일치에는 저장 오류를 반환한다.

가격 상한은 혜택 기간과 갱신 후 모두의 월 표시 가격 기준이다. 통화가 다르거나 세금/가격이 미확인하면 상한 충족으로 판정하지 않는다. 사용자가 지정한 최소 혜택 개월 및 필요한 기능 ID를 직접 비교하며, tool 일반 기능을 해당 행사 요금제 지원으로 추정하지 않는다. 확인되지 않은 필수 기능은 보류 사유로 앱에 표시한다. 가격 환산이나 절감액은 만들지 않는다.

과거 시도/접수 기록이 있는 같은 행사에서 가격·기간·자격·마감·상태가 바뀌면 정정 안내다. 새 자격이 불충족이어도 기존 잘못된 안내를 바로잡는 정정은 현재 관심·숨김·이메일 동의와 수신 시간/한도를 지켜 허용한다. 기능만 바뀐 경우에는 현재 필요한 기능에 영향이 있거나 기능 조건을 지정하지 않은 수신자에게만 정정한다. 일반 권유와 정정을 구분해 문구와 보류 이유를 표시한다. 앱 수신을 끈 경우도 기존 카드의 정정 이력은 읽을 수 있으나 새 카드는 만들지 않는다.

legacy 날짜 키는 당시 중요 사실을 알 수 없으므로 첫 hash 기준선은 별도 보류 사유로 기록한다. 과거 시도/접수가 있으면 이관만으로 새 이메일을 보내지 않는다. 이미 저장된 불변 기록과 실제 접수 상태는 바꾸지 않는다. 이후 기준선에서 실제로 바뀐 내용은 정정 가능하다. 미시도 legacy 큐는 취소하고 최신 검증 버전으로 재계획할 수 있다.

## 검증 및 범위

실제 SQLite migrations와 실제 API/전달 모듈, 고정 시각, 메모리 JSON fixture, 네트워크 차단 provider mock을 사용한다. RED 원본 8개와 정책 관찰을 보존한다. 추가로 재시도 무효화, 오래된 source/generator, 삭제 경합, 소유권, export, 기존 데이터 이관을 검증한다. 실제 사업자 연결/수신·무인 스케줄러, VoiceOver/OS zoom 증거는 별도의 미충족 항목으로 유지한다. 고정152 gates/38groups/9areas와 점수는 바꾸지 않는다.

## 구현 보완

같은 사실의 검수 번호 증가에는 event identity를 유지하고 A→B→A에는 새 event revision을 쓴다. 개인 결제는 공개 source head에 넣지 않는다. 설정 없는 기본 결제 알림도 현재 소유 구독 payload와 설정 부재를 DB에서 검증한다. 마감 전 정정 payload도 원래 기한 뒤에는 재시도하지 않는다. 이전 자료 실행은 최신큐 취소·빈 요약 슬롯 소비를 할 수 없다. 자세한 실제 범위와 남은 한계는 V15 검증 기록에 남겼다.
