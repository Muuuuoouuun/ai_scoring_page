**고객에게 줄 가치 — 필요한 기능을 유지하면서 구독 비용과 결제 시점을 스스로 결정한다.**

고객은 ‘무엇을 구독하는지’, ‘언제 얼마가 나가는지’, ‘같은 일을 더 적은 비용으로 할 수 있는지’를 한 흐름에서 확인한다. 기존 서비스의 기능·사용 목적·관심·대안 정보와 구독 정보를 연결하는 것이 이 기능의 제품상 의미다. 비용을 줄이는 것과 유용한 서비스를 계속 쓰는 것을 함께 고려한다.

개인 구독과 업무용 AI·SaaS를 우선 지원한다. 카탈로그에 없는 다른 구독도 직접 정리할 수 있다. 다만 기능·대체재·할인 평가의 운영 범위는 검수 가능한 AI·SaaS부터 넓힌다.

| 설계 방향 | 장점 | 한계와 결정 |
|---|---|---|
| 수동 구독 관리 + 조건이 확인된 절약 비교 | 계정 연동 없이 시작하고 고객의 실제 요금제를 반영 | 입력 부담이 있으므로 적은 필드와 점진적 보완으로 시작; 첫 출시로 제안 |
| 결제 내역 자동 연결 + 고급 분석 | 반복 입력 부담을 줄일 수 있음 | 연결 범위·데이터 정확성·고객 수요를 확인한 후 확장 |
| 할인·최저가 탐색 중심 | 구매를 앞둔 고객에게 바로 도움 | 사용 기간·갱신가·필요 기능을 놓치기 쉬워 개인 구독 정보에 연결된 보조 기능으로 운영 |

**개인 페이지 구조 — ‘내 구독·비용’과 ‘절약 제안’을 기존 도구함 안에 둔다.**

1. 상단 요약: 월 환산 고정비, 이번 달 확인된 결제, 이번 달 남은 예정액, 가까운 다음 결제.
2. 구독 목록: 서비스·플랜·사용 목적·금액·통화·주기·다음 결제·갱신 상태. 월 환산과 원래 청구액을 함께 표시.
3. 기간별 보기: 달력 또는 날짜순 목록과 월별 비용 막대. 3개월·12개월·직접 지정 기간을 바꿔 확인.
4. 절약 제안: 조건에 맞는 소수 제안, 예상 비용 차이와 확인할 내용. 제안이 없으면 현재 유지 이유나 부족한 정보를 안내.
5. 서비스 상세 연결: 기능·사용 기록·대안·공식 요금제/구독 관리 페이지. 사용 목적을 다시 입력하지 않게 한다.

도구를 등록할 때 ‘유료 구독인가요?’를 선택적으로 묻는다. 구독이라면 금액·통화·주기·다음 결제일을 입력하면 기본 계산이 가능하다. 모르는 항목이 있어도 초안은 보관하고, 해당 계산에 필요한 항목만 나중에 안내한다. 신용카드 번호·서비스 비밀번호는 입력 항목으로 두지 않는다.

**구독 기록 — 도구 사용 상태와 결제 계약 상태를 구분한다.**

| 정보 | 설계 기준 |
|---|---|
| 구독 식별 | 하나의 계약에 포함 서비스·계정 별칭·개인/업무 구분 연결; 같은 서비스의 복수 계약 허용 |
| 요금제·사용 권한 | 플랜명·필수 기능·좌석 수·이용량 한도·본인 부담 여부를 아는 범위에서 기록 |
| 청구 금액 | 결제 한 번의 금액·통화, 총액인지 좌석 단가인지, 세금 포함 여부, 개인 부담액 구분 |
| 주기·일정 | 청구 주기와 약정 기간 구분; 월·연·N개월 청구, 기준 결제일·시간대·남은 약정 청구; 기타 주기는 수동 일정으로 시작 |
| 할인·체험 | 적용 금액·대상 기간·종료일·이후 갱신 금액, 자격 확인 상태, 첫 유료 결제일 |
| 갱신·종료 | 갱신 예정·갱신 중단 확인·일시 정지·종료·미확인, 이용 가능 종료일, 별도의 해지 신청 기한 |
| 결제 확인 기록 | 고객이 확인한 결제 날짜·원래 통화 금액·실제 원화 청구액·환불/수수료, 입력 출처 |
| 개인화 조건 | 계속 필요한 기능·이용 예상 기간·선결제 한도·변경 의향·고객이 남긴 사용 빈도 |

사용 중단은 사용 상태만 바꾼다. 구독을 실제로 끊었다고 고객이 확인하지 않으면 결제 예정은 유지한다. 갱신 중단을 확인해도 이미 결제한 기간의 이용 종료일까지 도구를 사용할 수 있는 상태는 표현할 수 있어야 한다. 제공사 정책이 확인되지 않은 일시 정지는 청구 중단으로 추정하지 않는다.

비용은 구독 계약 단위로 한 번 집계한다. 같은 서비스가 여러 업무 모음에 있어도 중복하지 않는다. 한 번들에 여러 서비스가 포함되면 비용은 번들 계약에 귀속하고 포함 도구에는 ‘번들에 포함’이라고 표시한다. 개인 부담과 계약 전체 비용은 별도 보기로 두고 더하지 않는다. 부담 주체 미확인을 무료로 처리하지 않는다.

**비용 계산 — 월 환산·실제 결제·예상 결제를 다른 값으로 보여준다.**

| 표시 값 | 계산 규칙 | 고객이 알아야 할 것 |
|---|---|---|
| 월 환산 고정비 | 현재 유료 이용 기간의 정액 청구액 ÷ 해당 계약의 개월 수; 월 1, 분기 3, 연 12 | 비교용 값이며 이번 달 빠져나갈 돈이 아님 |
| 확인된 결제 | 선택 기간에 발생한 확인 결제에서 같은 기간에 발생한 확인 환불을 차감 | 환불은 실제 반영일 기준이며 원 결제와 연결; 수동 내역을 완전한 실지출로 부르지 않음 |
| 예상 결제 | 선택 기간에 발생하는 예정 결제 이벤트의 합 | 다음 결제일·갱신 여부·할인 종료·가격 조건에 따라 계산 |
| 기간 전체 전망 | 같은 기간의 확인된 결제 + 아직 확인되지 않은 예정 결제 | 확인된 이벤트와 연결해 중복 합산 방지 |
| 할인 종료 후 비용 | 확인된 할인 종료 다음 주기의 정상가로 별도 계산 | 한시적 할인 가격을 계속 유지된다고 가정하지 않음 |
| 외화 구독 | 원통화별 합계 우선, 선택한 기준 통화로 환산할 때 환율·기준일 표시 | 미래 환율·카드 수수료·세금 미확정분은 추정 또는 별도 미확인 |

갱신 중단 상태라도 현재 선결제 이용 기간 안에 있으면 그 기간의 월 환산액은 보여줄 수 있다. 이용 종료일과 갱신 중단에 따른 변화를 함께 표시하고 남은 약정 청구는 유지한다. 예정 결제 0건은 실제로 남은 청구가 없다고 확인할 수 있는 경우에만 표시한다. 아직 유료로 전환되지 않은 체험은 현재 정액 합계와 별도로 두고 확인된 첫 유료 결제를 일정에 표시한다.

금액·세금·갱신가·다음 결제일 중 필요한 정보가 없으면 해당 집계의 불완전함과 누락 항목 수를 밝힌다. 사용량 과금은 확인된 지출과 고객이 정한 예산/예상치를 구분하고 정액 합계에 숨겨 넣지 않는다. 가격이 바뀌었다는 소식만으로 기존 계약의 실제 갱신 가격을 덮어쓰지 않는다.

원래 계약 금액과 청구 기록은 보존하고 환산은 표시 단계에서 한다. 통화 단위의 정확한 산술과 일관된 반올림 규칙을 사용한다. 화면별로 동일한 계약이 다르게 합산되지 않게 하며, 연간 예상액은 월 환산액을 무조건 12배하는 방식으로 만들지 않는다.

일정은 계약의 달력 주기와 기준일을 사용한다. 매월 결제를 30일마다 발생하는 것으로 처리하지 않는다. 31일·윤년·기준 시간대를 다루며 짧은 달의 처리 방식은 제공사에서 확인한 규칙을 따른다. 미확인 미래 일정은 예상으로 표시하고 수정할 수 있게 한다. Stripe는 1월 31일 기준 월 구독이 2월 말 이후 다시 3월 31일로 이어지는 사례를 설명한다. 모든 서비스가 같은 정책이라는 뜻은 아니다. [Stripe — Billing cycle](https://docs.stripe.com/billing/subscriptions/billing-cycle).

요금제 변경의 환불·추가 청구·일할 정산은 제공사의 견적이나 확인된 정책을 적용한다. 정보가 없으면 비용 차이를 확정하지 않는다. Stripe의 문서에도 구독 변경 시 일할 정산을 다루는 별도 설정과 동작이 설명되어 있다. 이는 서비스별 조건 확인이 필요하다는 기술 참고이며, 이 제품에 Stripe를 도입한다는 결정은 아니다. [Stripe — Prorations](https://docs.stripe.com/billing/subscriptions/prorations).

**계산 예시 — 같은 구독이라도 조회 목적에 따라 금액이 다르다.**

가상 서비스 A는 매월 1일 20,000원, B는 매년 10월 1일 120,000원을 청구한다. 현재 시점은 2026-09-11, 두 구독은 갱신을 유지하며 가격·세금은 고정이고 별도 비용이 없다고 가정한다.

| 질문 | 답 | 근거 |
|---|---|---|
| 현재 월 환산 고정비는? | 30,000원 | 20,000 + 120,000 ÷ 12 |
| 2026년 10월 예상 결제는? | 140,000원 | A 20,000 + B 연 결제 120,000 |
| 2026년 11월 예상 결제는? | 20,000원 | A만 결제 예정 |
| 2026년 10~12월 예상 결제는? | 180,000원 | A 3회 60,000 + B 1회 120,000 |
| 2026년 10월~2027년 9월 예상 결제는? | 360,000원 | A 12회 240,000 + B 1회 120,000 |

2026-09-11에 B의 갱신 중단을 확인했고 9월 30일에 이용이 끝나는 경우, 10~12월 예정액은 A의 60,000원이다. 이전에 지불한 B의 금액을 9월 환불로 추가하지 않는다. 별도로, 원래의 갱신 유지 사례에서 10월 B 결제 120,000원이 확인 기록에 들어오면 해당 예정 이벤트를 연결해 같은 기간 전망에 두 번 더하지 않는다.

**절약 알고리즘 — 필요한 기능과 계약 조건을 지키는 후보만 같은 기간에 비교한다.**

1. 고객의 목적과 현재 구독을 연결한다. 필요한 기능·서비스 유지 조건·예상 사용 기간·선결제 가능 금액을 확인하고 모르는 항목은 미정으로 둔다.
2. 같은 서비스의 월/연 전환·낮은 요금제·좌석 조정·적용 가능한 할인, 기존 도구의 겹치는 기능, 검수한 대안을 후보로 만든다.
3. 필수 기능·한국어·파일 처리·플랫폼·이용량·협업 조건을 확인한다. 기능이나 자격 미확인은 확인 필요로 분리하고 최적안으로 확정하지 않는다.
4. 고객이 선택한 시작일·종료일까지 현재 구성을 유지할 때의 예정 결제와 각 대안의 예정 결제를 계산한다. 할인 종료, 중복 구독 기간, 전환 수수료, 확인된 환불을 포함한다.
5. 조건을 충족한 후보를 예상 비용, 선결제 부담, 필요한 변경의 정도로 비교한다. 먼저 최소 변경안을 제시하고 더 많이 절약하는 안·단기 이용에 맞는 안이 다를 때 차이를 설명한다.
6. 카드에 예상 차이·다음 결제·필요한 행동·잃는 기능·근거·확인일을 표시한다. 보류·관심 없음·조건 수정·현재 유지도 결과로 남긴다.

비용이 적다는 이유로 필요한 기능이 없어지는 안을 동등한 대안으로 표시하지 않는다. ‘최소 비용’은 검토한 후보와 입력 조건 안에서의 비교 결과로만 설명한다. 불확실한 업무 효율이나 학습 시간을 임의의 금액으로 환산해 절약액에 섞지 않고 전환 부담으로 별도 표시한다.

**비교 기간의 예상 순절감액 = 현재 구성을 유지할 때의 향후 순지출 − 변경안의 향후 순지출.** 양쪽 모두 같은 기간의 청구·수수료와 확인된 환불을 반영한다. 변경안에는 새 청구·전환 비용·중복 기간을 포함한다. 이미 낸 금액은 원칙적으로 양쪽의 과거 기록으로 남기며 돌려받는다는 근거가 없으면 절약액에 넣지 않는다.

첫 버전은 구독 한 건의 요금제/주기와 검수한 소수 대안을 비교한다. 복수 구독 최적화에서는 대체 후 필수 기능이 모두 남는지, 같은 서비스에 서로 다른 플랜을 동시에 적용하지 않는지, 할인끼리 함께 적용되는지를 구성 전체로 다시 확인해야 한다. 서로 배타적인 두 제안의 금액을 합산하지 않는다.

**더 싸게 구매하는 방법 — 가격과 자격·기간·갱신 조건을 한 묶음으로 보여준다.**

| 제안 후보 | 함께 확인할 조건 |
|---|---|
| 같은 서비스의 연간 결제 | 사용 예상 기간, 선결제액, 동등한 기능, 중도 변경·환불 조건 |
| 낮은 플랜·좌석 조정 | 실제 필요한 기능·용량·협업 인원과 줄어드는 권한 |
| 공식 프로모션·쿠폰 | 적용 대상·신규/기존 고객·마감일·중복 적용·첫 기간 가격·정상 갱신가 |
| 학생·교육·단체 등 자격 할인 | 고객이 확인한 자격·서류·이용 목적, 만료 이후 조건 |
| 공식 구매 경로별 가격 | 통화·세금·플랜·기능·변경 조건이 같은지, 기존 계약 변경에 적용 가능한지 |
| 다른 서비스·기존 구독 조합 | 필요한 전체 기능, 새 학습·설정·자료 이동 부담, 남은 선결제 기간 |

등록된 공식 가격·프로모션을 출처·확인일과 함께 제공한다. 자격은 고객이 확인하며 직업·나이·학생 여부 등을 추정해 적용하지 않는다. 판매 경로는 공식 제공사 또는 확인된 공인 경로로 한정한다. 자동 갱신 가격과 기간 제한을 숨기지 않는다. 정보가 만료되면 재확인으로 돌리고 현재 이용 가능하다고 단정하지 않는다.

초기에는 관리자가 확인한 소수 제안을 제공한다. 할인 자동 수집은 이후 검수·갱신이 가능한 범위에서 확장한다. 제휴 수익 여부와 관계없이 일반 비교의 순서·조건을 유지하며 제휴 관계는 표시한다.

**개인화 예시 — 같은 가격이라도 적합한 선택이 달라진다.**

동일한 기능을 가진 가상 서비스의 월 플랜은 20,000원, 연 플랜은 선결제 192,000원이다. 사용은 결제 주기 시작일에 시작하고 월 플랜은 필요 기간 종료 시 다음 갱신을 중단할 수 있으며, 별도 비용·환불은 없다고 가정한다.

| 고객 상황 | 비교 결과 | 제안 문구의 방향 |
|---|---|---|
| 12개월 계속 사용할 예정, 선결제 가능 | 월간 240,000원, 연간 192,000원; 차이 48,000원 | ‘12개월 사용 조건에서 48,000원 적고, 지금 192,000원을 결제해요.’ |
| 8개월 프로젝트에서만 필요 | 월간 160,000원, 연간 192,000원 | ‘필요한 8개월 동안은 월간 결제가 총 32,000원 적어요.’ |
| 오래 쓸 수 있지만 선결제 한도 100,000원 | 연간 선결제 조건 미충족 | 월간 또는 다른 조건 충족안 제시; 연간을 적합한 최저가로 표시하지 않음 |
| 지금 쓰는 다른 구독으로 필요한 기능을 모두 해결 가능 | 기존 플랜에서 가능한지와 전환 부담 확인 필요 | 바로 해지 권유하기보다 예시 작업으로 대체 가능성을 확인한 뒤 갱신 재검토 |

**고객 경험 — 절약을 압박하지 않고 판단에 필요한 내용을 제공한다.**

첫 화면은 ‘구독을 많이 쓰고 있어요’보다 ‘다음 결제와 비용을 확인해보세요’로 안내한다. 추천은 실제 사용 기간과 필요한 기능을 설명하는 방식으로 제공한다. 오랫동안 이 사이트에 오지 않았다는 이유만으로 외부 서비스를 쓰지 않는다고 판단하지 않는다.

고객은 제안을 저장하고 공식 관리 페이지에서 직접 변경한다. 돌아와 변경 요금제·적용일·다음 금액을 확인하면 예정 일정을 갱신하고 이전 기록을 보존한다. ‘사용 안 함’ 클릭이나 관리 페이지 이동만으로 해지·환불·절약을 완료 처리하지 않는다. 실제 결제·해지 실행 자동화는 이 기획의 첫 출시 범위가 아니다.

재미는 업무별 도구 조합을 정리하고, 자신에게 맞는 구성의 이유를 이해하고, 확인된 비용 변화를 보는 데서 만든다. ‘예상 절약’과 ‘고객이 변경을 기록함’, ‘결제 내역으로 확인한 비용 변화’를 구분한다. 검증되지 않은 누적 절약 배지나 해지 개수 경쟁은 사용하지 않는다.

갱신·체험 종료 일정은 첫 버전에서 앱 안에 보여준다. 관심 프로모션의 앱 알림함·동의한 이메일은 통합 기획서 v0.6의 첫 출시 범위다. 갱신·체험 종료의 외부 재알림과 푸시 등 추가 채널은 후속 기능이다. 결제일과 해지 신청 기한이 다르면 둘 다 표시하며, 제공사에서 확인하지 않은 공통 해지 기한을 만들지 않는다.

**데이터와 출시 범위 — 수동 관리의 완성도를 먼저 검증한다.**

개인 계약·결제 기록·비용은 계정에 귀속되고 기본 비공개다. 공통 서비스·가격·할인 정보와 분리한다. 서비스 하나에 여러 계약이 연결될 수 있고, 계약 하나는 여러 포함 서비스를 가질 수 있다. 가격 근거·할인 조건은 버전과 유효 기간을 기록하며 고객의 실제 계약 금액을 소급 수정하지 않는다. 직접 수집한 결제 정보가 없는 첫 버전에서는 화면에 ‘입력한 내역 기준’을 표시한다.

| 단계 | 범위 | 검증할 고객 행동 |
|---|---|---|
| 첫 공개 | 구독 수동 등록·비용·요금제 비교, 검수한 대안, 해지 길잡이, 관심 프로모션의 앱 알림함·동의한 이메일 | 다음 결제·총액·해지 경로를 이해하고 제안과 관심 알림을 선택 |
| 반복 사용 | 사용 목적·기간 피드백, 복수 구독 조합 비교, 갱신·체험 종료 재알림 | 기록을 갱신하고 필요한 기능을 유지하며 실제 비용 변화 확인 |
| 확장 | 고객이 연결한 결제 내역·영수증 가져오기, 팀 비용·좌석 관리, 할인 탐색 고도화 | 입력 부담 감소와 더 정확한 비용 관리가 실제로 확인됨 |

‘연 결제가 있는 달’, ‘같은 도구의 복수 계약’, ‘번들’, ‘갱신 중단’, ‘기간 한정 할인’, ‘부분 환불’, ‘외화·세금 미확인’, ‘사용량 과금’, ‘확인 결제와 예정 결제 중복’, ‘31일·윤년’, ‘필수 기능을 잃는 싼 대안’을 출시 평가 사례에 포함한다. 수치뿐 아니라 고객이 왜 월 환산과 청구액이 다른지 설명할 수 있는지도 확인한다.

유익은 제안 클릭률보다 구독 정보를 다시 확인·갱신하는 행동, 추천 조건 이해, 실제 업무에 필요한 기능 유지, 확인된 비용 변화로 판단한다. 비교 기준과 기간을 고정한 예상 절약은 가정에 의존하는 추정이며 실제 절약 성과와 구분한다. 고객이 여러 변경을 했을 때는 구독 구성 전체를 기준으로 다시 계산해 한 차이를 여러 추천의 성과로 중복 집계하지 않는다.
