# V11 업무 검색·추천 관련성 개선

승인 근거: 사용자는 전체 목표 달성을 위한 개선을 모두 승인하고 권장안으로 진행하도록 요청했다. 기존v0.6의 이름·동의어·기능/업무 태그·구조화 조건 기반 탐색 방침을 적용한다. 추가 승인 없이 현재 실패를 수정한다.

대안은 (1) 기존 검색을 토큰/업무 개념/제외 조건과 출처 있는 근거로 보완, (2) 고정 동의어만 추가, (3) 외부 의미 검색 서비스 도입이다.1번을 채택한다.2번은 문장·부정 표현 실패를 해결하지 못하며3번은 현재20개 카탈로그에 별도 비용/키/개인 질의 전송 경로를 추가한다.

## 결과와 범위

- 긴 한국어 업무 설명을 유용한 토큰과 일반 업무 개념으로 분리한다. 특정 시험 문장이나 제품별 순위를 하드코딩하지 않는다.
- 명시적 ‘말고/제외/빼고/원하지 않음’의 대상 제품·분야·유형을 긍정 의도와 구분한다. 해석한 제외 조건을 화면에 보여 수정 가능한 질의로 유지한다. 지원으로 확인되지 않은 조건은 충족했다고 말하지 않는다.
- 기능명/설명, 용례, 제품명/별칭에 직접 연결된 근거를 사용하며 기능의 condition/sourceUrl를 함께 보존한다. 넓은 분야 일치보다 직접 기능 일치를 우선한다. 개인 적합 확률이나 성능 점수를 만들지 않는다.
- 무료 필터는 제품의 무료 플랜 존재를 뜻한다. 기능별 무료 여부는 별도이며 매칭된 기능의 유료/한도 조건을 추천 표면에 표시한다. 빈 condition을 무제한 지원으로 해석하지 않는다.
- category/kind/free/korean/owned 필터는 결과가 없어도 완화하지 않는다. 기존 Explore, 전체검색의 도구 결과, WebMCP 모두 같은 함수를 사용한다. 공개 콘텐츠 전체검색/커뮤니티의 별도 검색 방식은 유지한다.
- 추가로 내 도구함을 불러오는 동안 빈 보유 목록을 확정된 무결과처럼 표시하지 않고, 다른 계정으로 전환되면 이전 보유 목록을 사용하지 않는다.

## 구성과 검증

순수 `lib/catalog-search.ts`에서 카탈로그 배열·질의·필터를 받아 해석된 조건, 관련도, 매칭된 기능/용례를 계산한다. `lib/catalog.ts`의 기존 함수는 같은 입력/기존 필드를 유지하는 wrapper다. Recommend는 출처 있는 근거를 렌더링하며 Explore는 해석한 제외 조건을 표시한다. 서버 API/DB/외부 제품 정보는 변경하지 않는다.

현 실패를 재현하는 동작 테스트를 먼저 작성한다. 문자열 구현 비교 대신 실제 등록 후보의 순위·제외·하드필터·근거 원본 유지·미등록 목적/긍정 문맥 경계를 검증한다. 사전 고정V10 20질의를 변경하지 않고 재실행하고, 독립적으로 먼저 고정한 새 질의도 평가한다. 부족한 사례는 실패로 남기거나 일반 규칙을 수정하고 새 보류표본을 추가한다. 데스크톱/모바일 실제 UI와 주요 검색 경로를 확인한 뒤 타입·전체 테스트·Sites 빌드 및 정확한 소스의 비공개 배포를 수행한다.

외부 이메일/정기 작업, 실제 사용자 과제·계정 격리·확대/스크린리더는 이 수정의 완료로 대신하지 않는다. 고정 점수 기준과 전체88점 목표는 유지한다.
