# 서비스 확충·개인 연결 Implementation Plan

> **For agentic workers:** root가 Site를 수정·검증·배포하며 독립 에이전트는 공식 자료 조사와 읽기 전용 검토만 맡는다. 기존 사용자 전체 승인으로 계획 승인 대기를 반복하지 않는다.

**Goal:** 최신 목표의 서비스 범위와 개인 등록→관련 기능/혜택 흐름을 실제 사이트에 구현한다.

**Architecture:** 기존 Vinext/D1 인증·개인 기록을 유지한다. 기능 유사도와 서비스 식별은 순수 함수, 서비스별 정보는 독립 컴포넌트, 혜택의 모집 상태는 기존 promotion-facts에서 공통 처리한다.

**Tech Stack:** TypeScript, React/Vinext, Cloudflare D1/R2, 기존 Node SQLite API harness, Sites.

---

- [x] `tests/tool-similarity.test.mjs`: 같은 카테고리만 같은 후보를 제외하고 공통 지원 기능의 조건·공식 근거를 보존하는 실패를 확인한다. `lib/tool-similarity.ts`의 `similarTools(source,items)`로 지원/조건부 기능별 작업 태그를 겹쳐 비교하고 관련도·근거를 반환한다. `catalog.relatedTools`와 추천 페이지에서 공용으로 쓴다.
- [x] 내 도구함의 서비스 정보 컴포넌트에 같은 toolId의 구독, 공식 업데이트, 대안 추천, 관련 혜택을 모은다. 기록 없음/직접 입력/미확인 상태와 다음 행동을 구분한다. 추천은 상세 비교로 이어진다.
- [x] 직접 입력한 서비스의 이름/공식 주소와 카탈로그 연결 후보를 보여준다. 실제 계정 데이터 연결과 구분한다. 기존 API를 바꿀 때 중복 target·다른 소유자·기존 기록 수정의 검증을 먼저 추가한다.
- [x] 조사 결과의 14개 카탈로그 후보·실제 로고·기능 출처를 검수해 `data/catalog.json`과 `public/logos`에 통합한다. 협업·PMS·음성·영상 분류와 검색 동의를 일치시킨다. 기존20개와 중복/깨진 출처/날짜 조작이 없는지 확인한다.
- [x] 3개 공식 프로그램 조사 후 `Promotion`에 상시 모집 여부를 명시한다. null 종료일만으로 모집 중으로 간주하지 않는다. 확인 기간이 지난 상시 프로그램은 보류한다. 기존 날짜형 마감·정정·알림·이메일 경계를 회귀 검증한다.
- [x] 새 혜택을 개별 지역/자격/요금/갱신 문구로 렌더하고 내 서비스/대안에서 연결한다. 사용자 수신 동의는 변경하지 않는다.
- [x] 해당 순수 함수/API 테스트와 전체 영향 회귀, 타입 검사, Sites 빌드, 데스크톱·390px 핵심 동선, 독립 검토 후 root가 커밋·push·기존 비공개 사이트 배포를 완료한다.

실제 외부 계정 데이터 연결은 사용자 우선 범위와 정상 제공사 인증 조건을 확인해 별도 실행 단계로 반영한다. 이 파일의 정보 연결 구현만으로 계정 연결을 완료한 것으로 평가하지 않는다.


완료 기록: Sites 비공개 V22, 2026-09-15. 287 테스트·타입 검사·빌드 통과. 데스크톱/390px 핵심 흐름과 운영 34개 결과·Asana 추천·4개 혜택 확인. 실제 외부 계정 연결은 미구현이며 상위 목표는 진행 중으로 유지한다.
