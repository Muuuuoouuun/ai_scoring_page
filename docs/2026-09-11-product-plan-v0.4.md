**정체성 — 내가 쓰는 서비스를 정리하고, 필요한 기능을 찾아 더 잘 활용하며, 내 상황에 맞게 구독 비용을 관리하는 AI·SaaS 서비스.**

고객은 사용하는 서비스·구독·관심사를 한곳에 모으고, 하고 싶은 일을 자신의 말로 검색한다. 서비스는 기존 도구로 가능한 방법, 비교할 대안, 함께 활용할 도구와 안내를 근거와 함께 연결한다. 비용을 줄이고 싶을 때는 필요한 기능과 이용 기간을 유지할 수 있는 요금제·구독 조합을 비교한다. 사용 경험과 구독 조건은 다음 선택과 추천을 개선하는 맥락이 된다.

> 내가 쓰는 도구와 구독을 한곳에. 필요한 기능을 찾고, 나에게 맞는 비용으로 활용하세요.

제품의 중심 흐름은 **정리 → 필요한 일 검색 → 기능·비용 비교 → 사용 → 기록 → 활용·구독 재검토**다. 뉴스·행사·커뮤니티는 고객의 도구와 관심 업무에 연결되어 이 흐름을 풍부하게 한다. 개인 페이지에 쌓이는 정보가 검색·추천·비용 관리에 실제로 도움이 되어야 한다.

| 이번 버전의 핵심 결정 | 고객에게 생기는 변화 |
|---|---|
| 개인 페이지를 핵심 이용 공간으로 설정 | 사용 중·관심·시험 중 서비스를 정리하고 다음 방문에 이어서 사용 |
| 기능과 하고 싶은 일로 검색 | 제품 이름을 몰라도 필요한 것을 찾음 |
| 기존 서비스·유사 서비스·보완 도구를 관계로 연결 | 새로 찾은 도구가 나에게 왜 필요한지 판단 |
| 추천 이유와 적용 조건을 함께 표시 | 무엇이 맞고 무엇을 확인해야 하는지 이해 |
| 계정에 개인 기록 보관을 첫 출시 범위에 포함 | 브라우저와 기기가 달라도 자신의 도구함을 이어서 사용 |
| 구독 관리·기간별 비용·기본 절약 비교를 핵심 기능으로 포함 | 이번 달 지출과 앞으로의 결제를 이해하고 필요한 기능을 유지하며 비용 조정 |

개인 페이지 중심, 검색 중심, 발견 피드 중심의 세 방향을 비교하면, **개인 페이지와 목적 검색을 함께 중심에 두는 방향**을 제안한다. 검색은 처음 온 고객에게 바로 도움을 주고, 개인 페이지는 이미 쓰는 서비스와 작업을 기억해 다음 이용의 가치를 만든다. 발견 피드는 새로운 관심을 넓히는 입구로 유지한다. 개인화가 가능한 기록이 없어도 검색과 발견을 사용할 수 있어야 한다.

**고객과 우선순위 — 사용 편의와 친절함을 가장 먼저 검토한다.**

초기에는 리서치·보고서·콘텐츠 기획에 AI·SaaS를 쓰는 한국어 실무자를 고객 가설로 둔다. ‘처음 고르는 사람’, ‘이미 여러 서비스를 쓰는 사람’, ‘가볍게 새 활용법을 찾는 사람’의 방문 목적을 모두 수용하되, 깊이 검증할 업무는 소수로 시작한다.

| 내부 기능 선정 기준 | 제안 비중 | 판단 질문 |
|---|---|---|
| 고객 사용·친절함 | 40% | 처음에도 이해하고, 적게 입력하며, 막혀도 이어갈 수 있는가? |
| 실제 유익 | 30% | 찾는 수고·중복 구매·학습 부담을 줄이거나 실제 작업에 도움이 되는가? |
| 재미·재방문 동기 | 20% | 나다운 정리, 뜻밖의 활용법, 작은 성취, 경험 교류가 있는가? |
| 확장성·운영 지속성 | 10% | 같은 정보를 재사용하고 정확하게 유지할 수 있는가? |

이 비중은 도구 평점이나 추천 알고리즘의 가중치가 아니다. 정보 정확성·공개 범위에 대한 동의·기본 접근성은 별도로 충족해야 할 출시 조건이다.

**서비스 구조 — 네 메뉴와 공통 검색을 유지하고, 개인화가 필요한 곳을 연결한다.**

| 메뉴 | 주요 구성 | 고객의 대표 행동 |
|---|---|---|
| 발견 | 오늘의 발견, 짧은 활용 예시, 관련 소식·업데이트·행사 | 새로운 가능성을 보고 저장하거나 시도 |
| 도구 찾기 | 기능·목적 검색, 업무·조건 탐색, 도구 상세, 나란히 비교 | 필요한 일을 해결할 방법과 도구를 찾음 |
| 경험 나누기 | 사용 후기, 선택 질문, 활용 방법, 도구 조합 | 비슷한 상황의 경험을 참고하고 참여 |
| 내 도구함 | 내 서비스, 내 구독·비용, 업무별 모음, 절약 제안, 사용 기록·소식 | 사용·관심·구독 서비스를 정리하고 활용과 비용을 관리 |

메뉴 이름은 ‘내 도구함’으로 통일하고, 그 안의 중심 화면을 개인 페이지인 ‘내 서비스’로 구성한다. 별도의 중복 메뉴를 만들지 않는다. 공통 검색은 제품 이름·기능·하고 싶은 일·활용법을 받으며, 결과 유형을 표시한다. ‘전체에서 찾기’와 ‘내 도구함에서 찾기’를 명확히 구분한다.

처음 온 고객은 ‘하고 싶은 일로 찾기’와 ‘가볍게 둘러보기’로 시작한다. 기록이 있는 재방문자는 내 서비스와 하던 작업을 빠르게 열고, 관련 변화나 활용 제안을 확인한다. 메뉴 위치는 유지하고 내용의 우선순위를 조정한다.

**핵심 기능 1 — 개인 페이지: 내가 쓰는 서비스와 사용 맥락을 관리한다.**

단순한 관심 목록보다 넓게, 서비스별 상태·사용 목적·작업 모음·사용 경험을 연결한다. 가입 직후부터 긴 프로필을 작성하게 하지 않고 ‘쓰는 서비스 하나 추가’로 시작할 수 있게 한다.

| 개인 페이지 영역 | 담을 내용 | 대표 행동 |
|---|---|---|
| 내 서비스 | 사용 중·시험 중·관심 있음·사용 중단, 사용 목적 | 추가, 상태 변경, 고정, 공식 서비스 열기, 검색, 제거 |
| 업무별 모음 | ‘보고서 만들기’, ‘콘텐츠 제작’ 등 고객이 붙인 이름과 도구 | 모음 생성, 도구 연결, 순서 변경 |
| 서비스별 기록 | 요금제, 메모, 사용 결과, 선택 이유, 저장한 안내 | 필요한 항목만 추가·수정 |
| 내 구독·비용 | 결제 주기·금액·통화·다음 결제일·이용 종료일, 월 환산·기간별 비용 | 구독 추가, 일정 확인, 기간 변경, 결제 기록 |
| 절약 제안 | 결제 주기·요금제·할인·대안·구독 조합 비교 | 예상 비용과 잃는 기능 확인, 검토할 제안 저장 |
| 나에게 맞는 제안 | 기존 도구의 새 활용법, 대안, 함께 쓸 도구 | 추천 이유 확인, 비교, 관심 없음 표시 |
| 이어서 할 일·관련 변화 | 진행하던 비교, 저장한 안내, 내 서비스의 주요 변경 | 작업 재개, 변경 확인, 나중에 보기 |

서비스 추가 시 이름 검색과 자동완성을 제공한다. ‘쓰는 서비스 추가’에서는 사용 중, ‘관심 저장’에서는 관심 있음으로 상태를 표시하고 고객이 확인·변경할 수 있게 한다. 일반 조회나 링크 클릭으로 사용 중 상태를 자동 지정하지 않는다. 사용 목적·요금제·비용·메모는 선택 입력이다. 요금제를 모르면 ‘미정’으로 남기며 유료 기능 이용 가능 여부를 추정하지 않는다.

목록에 없는 서비스도 이름과 선택 URL로 개인 도구함에 추가할 수 있게 한다. 이 항목은 ‘내가 추가한 서비스·기능 정보 미확인’으로 표시하고 공개 카탈로그에는 자동 등록하지 않는다. 추후 공식 항목과 연결할 때는 고객이 확인하며 기존 메모와 상태를 보존한다. 같은 도구가 여러 업무 모음에 속해도 서비스 기록은 하나로 관리한다. 해당 서비스의 개인용·업무용 등 구독 계약은 여러 개 연결할 수 있으며 비용은 계약별로 집계한다. 번들 하나가 여러 서비스를 포함할 때는 같은 결제를 반복 합산하지 않는다.

기본 기록은 계정에 저장하고 여러 기기에서 이어서 이용한다. 탐색·검색·비교는 비회원도 가능하다. 비회원의 비교·선택 초안은 저장 위치를 밝히고, 계정 저장 시 보관할 항목을 확인한 뒤 옮긴다. 계정 접근 복구, 개인 기록 내보내기·삭제, 항목 제거 직후 실행 취소를 제공한다. 다른 계정으로 로그인한 경우 초안을 자동 합치지 않는다. 저장 실패 시 입력을 유지하고 재시도를 제공한다.

개인 서비스 목록·사용 목적·메모·비용은 기본 비공개다. 추후 공개 모음을 만들더라도 공개할 도구와 설명을 별도로 선택하고 미리 확인한다. 개인 메모나 비용이 함께 공개되지 않게 한다. 고객이 원하면 개인화에 사용할 관심 주제와 사용 목적을 바꾸거나 끌 수 있게 한다.

수동 구독 입력·기간별 비용·기본 절약 비교는 첫 출시의 핵심 범위다. 은행·결제 계정 연결, 자동 구독 감지, 자동 구매·해지, 이용량 수집은 후속 수요와 연동 조건을 확인해 검토한다. 실제 사용 빈도도 연결이나 고객 기록 없이 추정해 표시하지 않는다. 사용 중단 표시와 실제 구독 갱신 중단은 별도 상태로 관리한다.

**핵심 기능 2 — 기능·목적 검색: 제품 이름을 몰라도 고객의 말로 찾는다.**

‘PDF 요약’, ‘회의록’ 같은 짧은 검색어와 ‘여러 자료를 읽고 출처가 있는 보고서를 만들고 싶어’ 같은 문장을 모두 받는다. 입력 예시는 대표 업무와 연결하고, 질문을 단계적으로 답하는 탐색 방식도 함께 제공한다.

검색은 필요한 작업·기능과 중요한 조건을 구분한다. 언어·비용·입출력 형식·플랫폼·연동 방식·이미 사용하는 서비스가 관련 조건이다. 모든 항목을 묻지 않고 결과에 영향을 주는 것부터 사용한다. 예를 들어 ‘한국어 회의 메모에서 할 일을 뽑고 문서 앱으로 옮기고 싶어. 추가 결제 없이’라면 다음과 같이 이해한 내용을 수정 가능하게 보여준다.

> 할 일 추출 · 한국어 · 문서로 옮기기 · 추가 결제 없음
>
> ‘복사해서 옮기기’와 ‘자동으로 연결하기’ 중 원하는 방식을 선택할 수 있어요.

구체적인 서비스명·요금제를 아직 모르면 검색을 막지 않고 확인 가능한 결과를 먼저 보여준다. ‘추가 결제 없음’과 ‘누구나 무료’는 다르므로 현재 요금제에서 가능한지도 별도로 확인한다. 필수 조건에 영향을 주는 모호함은 짧게 확인하고, 결과를 바꾸는 해석을 숨기지 않는다.

| 결과 묶음 | 고객에게 설명할 것 | 다음 행동 |
|---|---|---|
| 지금 쓰는 서비스로 해보기 | 필요한 기능과 현재 요금제에서 가능한지, 준비할 것 | 활용 안내 열기 |
| 조건에 맞는 다른 서비스 | 해당 작업의 장점, 비용·제약, 기존 도구와의 차이 | 나란히 비교, 시험 중으로 저장 |
| 함께 쓰는 방법 | 각 도구의 역할과 연결 방식, 추가 비용·설정 | 조합 안내 확인 |

관련성이 확인된 묶음만 보여준다. 첫 추천 요약은 전체에서 최대 3개 방법을 제시하고, 더보기로 확장한다. 모든 검색을 세 묶음으로 억지로 채우거나 기존 도구라는 이유만으로 조건에 맞는 대안을 밀어내지 않는다. 도구뿐 아니라 이미 검토한 활용 안내와 조합도 해결 방법으로 검색한다.

필수 조건이 확인된 후보와 ‘확인이 필요한 후보’를 구분한다. 조건을 충족하지 못하는 제품을 적합한 결과로 제시하지 않는다. 결과가 없으면 ‘현재 등록·확인한 정보에서는 찾지 못했어요’라고 범위를 밝히고 조건 수정·다른 접근·등록 요청을 제공한다. 고객의 동의 없이 무료·언어·연동 조건을 완화하지 않는다.

**핵심 기능 3 — 연관 추천: 비슷함·보완·관심을 구분해 연결한다.**

| 연결 관계 | 고객이 받는 도움 | 설명 예시의 형식 |
|---|---|---|
| 이미 쓰는 도구의 다른 활용 | 보유한 도구로 가능한 일을 넓힘 | ‘사용 중인 서비스에서 이 작업도 할 수 있어요. 적용 요금제를 확인해보세요.’ |
| 비슷한 서비스·대안 | 같은 목적에 쓰는 도구의 차이를 이해 | ‘같은 문서 작업에 쓰이며, 파일 처리 조건이 달라 비교할 만해요.’ |
| 함께 쓰면 좋은 도구 | 기존 도구가 부족한 작업을 보완 | ‘초안 작성 다음 단계인 결과 정리에 연결해볼 수 있어요.’ |
| 관심과 연결된 발견 | 저장한 업무·기능과 관련된 새 가능성 발견 | ‘관심 주제인 리서치와 관련된 활용법이에요.’ |

위 문구는 표시 방식 예시이며 특정 제품의 기능을 주장하지 않는다. 실제 카드에는 사용한 관심·목적, 연결 이유, 중요한 제약, 출처와 확인일을 표시한다. ‘연동 가능’은 확인한 연결 방식과 요금제·방향·제한이 있을 때 사용한다. 복사·파일 내보내기로 이어지는 수동 조합은 자동 연동과 구별한다.

‘비슷하다’는 같은 회사나 같은 AI 분류에 속한다는 의미보다, 어떤 업무·기능이 겹치는지로 설명한다. 대안은 더 좋은 점과 포기할 점을 함께 보여주며, 여러 목적에 쓰이는 기존 서비스를 기능 하나만 겹친다고 불필요한 구독으로 단정하지 않는다.

개인화는 고객이 직접 고른 사용 목적·관심·조건을 우선한다. 관심 저장은 실제 사용이나 만족으로 간주하지 않는다. ‘관심 없음’, ‘이미 알고 있음’, ‘추천에 반영하지 않기’, 관심 설정 초기화를 제공한다. 피드의 탐색 제안은 관심을 넓힐 수 있지만 검색의 필수 조건은 계속 지킨다. 이용 기록이 없으면 선택한 목적과 편집자가 확인한 기본 추천으로 시작한다.

**추천·검색 알고리즘 — 확인된 정보를 찾고, 조건에 맞춰 설명 가능한 순서로 제시한다.**

1. **요청 이해:** 고객 표현에서 작업·기능·필수 조건·선호 조건을 구분한다. 추출한 조건은 고객이 수정할 수 있다.
2. **후보 찾기:** 등록된 서비스의 이름·별칭·기능·업무·활용법·조합을 검색한다. 내 도구함을 반영하도록 설정했다면 사용 중인 도구와 현재 목적을 함께 확인한다.
3. **조건 확인:** 알려진 미충족 후보를 제외하고, 필수 정보가 없는 후보는 ‘확인 필요’로 분리한다. 후보가 있는 요금제와 고객이 가진 요금제를 구별한다.
4. **순서 정하기:** 현재 작업과의 일치, 확인된 기능과 근거, 시작 부담, 기존 도구 활용 가능성, 개인의 명시적 선호를 반영한다. 단순 인기도·광고비로 일반 추천 순서를 결정하지 않는다.
5. **차이 보여주기:** 사실상 같은 후보만 반복하지 않도록 해결 방식의 차이를 보여주되 필수 조건은 유지한다. 검증되지 않은 ‘적합도 97%’ 대신 이유와 제한을 쓴다.
6. **설명과 피드백:** 각 설명은 실제로 순서 결정에 사용한 조건·근거에서 만든다. ‘도움 됨’, ‘목적과 다름’, ‘기능 정보가 다름’의 이유를 받아 조건·데이터·추천 방식을 개선한다.

첫 버전은 작은 카탈로그에 맞춰 **한국어 동의어·기능/업무 태그·구조화된 조건·검수한 관계를 이용한 검색과 추천**으로 시작한다. 자연어 입력을 받되 확실히 이해하지 못한 부분은 선택지로 보완한다. 처음부터 모든 표현을 이해한다고 약속하지 않는다. 개인 도구함 정보의 반영과 추천 이유 표시는 첫 버전에 포함한다.

카탈로그와 표현의 범위가 넓어지면 단어 검색과 의미 검색을 결합하는 방식을 비교 검증한다. Microsoft의 공식 문서는 하이브리드 검색을 전문 검색과 벡터 검색을 결합해 결과를 합치는 방식으로 설명한다. 이 개념을 확장 후보로 참고하며 특정 클라우드나 제품의 도입을 결정한 것은 아니다. [Microsoft Learn — Hybrid search](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview).

의미 검색이나 언어 모델은 후보를 찾고 입력을 정리하는 역할을 맡는다. 기능·요금제·연동 사실은 출처가 있는 구조화된 정보로 확인한다. 모델이 만든 관계를 검수된 기능으로 자동 발행하지 않는다. 의미 검색을 추가하더라도 필수 조건 확인은 별도로 유지한다. 검색 장애 시 키워드·필터·업무별 탐색을 이용할 수 있게 한다.

첫 버전은 실제 이용자가 적어도 작동하는 방식으로 설계한다. 비슷한 고객의 행동을 활용한 추천은 충분한 실제 사용 기록과 검증이 쌓인 뒤 검토한다. 개인 메모·업무 자료를 기본 검색 색인에 넣거나 외부 모델로 일괄 전달하지 않는다. 개인화에 쓰는 정보의 범위를 설명하고 필요한 구조화 항목만 사용한다.

**핵심 기능 4 — 상세·비교: 추천을 이해하고 선택할 근거를 준다.**

상세 화면은 ‘이럴 때 좋아요’, ‘시작 전에 확인하세요’, ‘이렇게 써볼 수 있어요’를 먼저 보여준다. 비교는 같은 작업과 조건을 기준으로 잘 맞는 일·시작 난이도·비용·무료 범위·한국어·입출력·제약을 나란히 제공한다. 기능은 가능/불가능 외에도 요금제 제한·확인 필요를 구분한다.

도구의 전체 평균보다 이번 작업의 근거가 먼저다. 평가 점수를 제공할 때는 과제·사용 조건·시점·표본·평가자를 함께 표시하고 미확인을 0점으로 바꾸지 않는다. 비교 후보는 최대 3개를 한 번에 다루며 하나만 선택한 상태에서도 현재 선택을 유지한다.

결정은 ‘시험해볼래요’, ‘지금 쓰는 도구를 계속 쓸래요’, ‘나중에 볼래요’로 표현하고 개인 도구함에 이어진다. 저장된 요금제가 있더라도 오래된 정보라면 확인 시점을 알리고 수정할 수 있게 한다.

**핵심 기능 5 — 짧게 따라하기: 선택 후 실제 작업의 시작을 돕는다.**

준비물·가능한 요금제·예시 입력 → 작업 순서 → 결과 확인 → 막힘 해결의 순서로 안내한다. 예시 자료와 복사 가능한 입력을 제공해 고객이 개인 업무 자료를 제출하지 않고도 연습할 수 있게 한다. 소요 시간은 측정·추정 조건을 밝힌다.

첫 버전은 고객이 외부 도구에서 실행한다. ‘예시 복사’, ‘공식 도구에서 열기’처럼 실제 행동을 버튼에 표시한다. 돌아오면 ‘해봤어요 / 막혔어요 / 나중에 할게요’를 선택하고 결과를 개인 기록에 남긴다. 외부 사이트 클릭을 작업 성공으로 집계하지 않는다.

**핵심 기능 6 — 발견·소식: 나에게 연결되는 새로운 가능성을 보여준다.**

발견 카드는 결과 예시·어울리는 상황·시작 조건을 담고 대표 행동 하나를 중심에 둔다. 초반에는 편집자가 검토한 소량의 카드와 ‘이번 주 한 가지 해보기’를 운영한다. 사용 중인 서비스의 새로운 기능, 관심 업무의 활용법, 관련 소식·행사를 연결하고 추천 이유를 설명한다.

업데이트는 무엇이 달라졌는지, 어떤 사용자·요금제에 해당하는지, 확인할 행동이 무엇인지 알려준다. 발표 여부와 직접 테스트 여부를 구분한다. 새 소식이 없으면 저장한 작업을 이어서 보게 한다. 과장된 긴급성이나 읽지 않은 알림 수로 재방문을 유도하지 않는다. 외부 알림과 정기 브리핑은 별도 수신 설정이 있는 확장 단계에서 도입한다.

**핵심 기능 7 — 경험 나누기: 개인 기록에서 부담 없이 참여한다.**

짧은 콘텐츠 반응, 비공개 사용 기록, 공개 사용 후기, 질문·오류 제보를 구분한다. 공개 후기는 어떤 작업·시점·요금제에서 잘됐고 막혔는지 알 수 있게 받는다. 반응을 성능 평점이나 실사용 인증으로 바꾸지 않는다.

다른 고객의 안내를 저장하고 따라 해볼 수 있으며, 공개할 때는 범위를 먼저 확인한다. 출처·원 작성자·업체 관계를 표시한다. 첫 출시는 검토된 경험 열람·짧은 반응·질문 접수로 운영하고, 공개 작성·도구 모음 공유·답변은 운영 여력과 참여가 확인된 후 확장한다. 질문은 접수 상태와 답변 확인 경로를 제공한다.

**핵심 기능 8 — 구독 관리·비용 최적화: 필요한 기능을 유지하면서 지출을 조정한다.**

‘내 구독·비용’에서는 구독별 요금제·결제 주기·금액·통화·다음 결제일과 갱신 상태를 관리한다. 기능과 사용 목적은 기존 내 서비스 기록에 연결한다. 직접 등록한 서비스도 비용을 관리할 수 있지만 검증하지 않은 대체 기능이나 할인은 추천하지 않는다.

| 개인 비용 화면 | 고객이 확인할 내용 |
|---|---|
| 월 환산 고정비 | 월·분기·연간 정액 구독을 월 기준으로 나란히 비교; 실제 이번 달 결제액과 구분 |
| 이번 달 결제 | 고객이 확인·입력한 결제 내역과 앞으로의 결제 예정액을 각각 표시 |
| 앞으로 3개월·12개월·선택 기간 | 해당 기간의 결제 일정으로 예상 지출 계산, 가격 미확인·변동비·환율 조건 표시 |
| 다음 결제·체험 종료 | 다음 청구일, 이용 종료일, 갱신 여부, 확인된 변경 기한 |
| 절약 제안 | 유지·월/연 전환·요금제 조정·할인·대안의 같은 기간 비용과 기능 차이 |

예를 들어 월 20,000원 구독과 연 120,000원 구독을 보유하면 월 환산 고정비는 30,000원이다. 두 구독 모두 해당 월에 결제한다면 그달 결제 예정 합계는 140,000원이다. 가상 예시이며 실제 보유 서비스나 가격을 뜻하지 않는다. 미입력 비용은 0원으로 합산하지 않고 ‘금액 확인 필요’ 개수를 보여준다.

절약 제안은 고객의 필수 기능·예상 사용 기간·선결제 가능 금액·서비스 변경 의향을 반영한다. 같은 서비스의 결제 주기·요금제·공식 할인부터, 기존 서비스로 대체할 수 있는 기능과 구독 조합까지 비교한다. 추천 카드에는 비교 기간·예상 비용 차이·지금 필요한 결제액·줄어드는 기능·할인 자격·갱신 가격·적용 시점과 근거를 함께 표시한다.

‘월 20,000원 또는 연 192,000원’이라는 가상 선택지는 동일 기능으로 12개월 사용하면 연간 48,000원 차이가 난다. 그러나 8개월만 필요하다면 월간 결제 총 160,000원이 더 적다. 사용 기간과 결제 조건을 고려해 고객별로 다른 제안을 해야 한다.

이미 지불한 연간 비용은 해지 검토만으로 돌려받는 금액으로 표시하지 않는다. 확인된 환불·일할 정산·중복 이용 기간·전환 비용을 반영하고, 갱신 중단은 다음 결제부터의 변화로 설명한다. 서로 동시에 적용할 수 없는 할인·플랜 변경의 절감액을 더하지 않는다. ‘예상 절약’, ‘변경했다고 기록’, ‘결제 내역으로 확인한 비용 변화’를 구분한다.

첫 출시에는 확인된 가격·조건에 기반한 비교와 공식 관리 페이지 연결을 제공한다. 외부에서 고객이 변경한 뒤 구독 기록을 갱신한다. 페이지를 열었다고 구매·해지·절약이 완료됐다고 표시하지 않는다. 공식 프로모션과 적용 자격을 확인한 할인부터 다루며, 확인한 범위를 넘는 ‘최저가 보장’을 하지 않는다.

**사용·유익·재미 — 개인화의 가치를 고객이 직접 느끼게 한다.**

| 고객의 고민 | 쉬운 사용 | 유익 | 재미·다시 찾을 이유 |
|---|---|---|---|
| ‘뭘 쓰고 있는지 흩어져 있어’ | 서비스 몇 개를 추가하고 업무별로 묶음 | 도구와 사용 목적을 한곳에서 확인 | 나에게 맞는 도구함을 만드는 만족 |

이 표는 검증할 고객 경험 가설이다. 재미는 실제로 새롭게 알게 된 점·다시 해보고 싶은 일·정리한 내용을 꺼내 쓰는 행동으로 확인한다. 많은 도구를 저장하거나 오래 머문다는 이유만으로 유익하다고 판단하지 않는다.

**대표 경험 — 서비스 등록과 검색이 서로의 가치를 높인다.**

가상의 고객이 문서 도구와 AI 서비스를 사용 중으로 추가하고 목적을 ‘자료 조사·보고서’로 설정한다. 이후 ‘한국어 자료 여러 개를 출처와 함께 정리하고 싶어. 추가 결제 없이’라고 검색한다. 아래 흐름은 실제 제품 기능이 아닌 설계 예시다.

| 순서 | 고객의 행동 | 서비스의 도움 |
|---|---|---|
| 정리 | 사용 중인 서비스 2개 추가 | 아는 항목만 입력하고 바로 개인 페이지 생성 |
| 검색 | 원하는 결과와 조건을 문장으로 입력 | 이해한 업무·필수 조건을 보여주고 수정 허용 |
| 이해 | 기존 도구 방법과 대안 확인 | 확인된 기능·요금제·출처를 바탕으로 차이 설명 |
| 시도 | 가장 쉬운 방법으로 예시 작업 시작 | 준비물·복사 입력·외부 실행·막힘 해결 안내 |
| 기록 | 계속 사용할 방법을 모음에 저장 | 도구·목적·안내·결과를 연결해 보관 |
| 재방문 | 저장한 작업을 열고 관련 제안 확인 | 같은 서비스의 다른 활용법과 확인할 변화 제공 |

요금제나 기능 정보가 없으면 ‘가능’이라고 채우지 않고 확인할 정보를 알려준다. 고객이 도구를 등록하지 않으면 전체 검색으로 같은 작업을 시작할 수 있다. 모든 고객에게 설문·회원가입·공개 후기를 먼저 요구하지 않는다.

| 개인화 고도화 | 상황과 피드백에 더 잘 맞는 추천 | 충분한 기록, 일반 추천 대비 유익 검증 |
| 단계별 학습·행사 | 도구 선택에서 반복 활용·교류로 발전 | 후속 실습과 모임 수요 |
| API·서비스 연결 | 실제 작업과 결과를 더 적은 이동으로 처리 | 반복 작업과 연동 비용의 타당성 |
| 새로운 직무·언어 | 같은 경험을 다른 업무에 적용 | 분야별 고객 요청과 검수 역량 |

기본 개인 보관·검색·비교·구독 비용 확인·단순 절약 비교는 초기 핵심 가치다. 유료화 후보는 복수 구독 조합 비교·장기 비용 분석·자동 동기화·맞춤 브리핑과 팀 공동 관리로 두며, 수요와 지불 의향을 확인한 뒤 정한다. ‘이미 가진 도구로 해결’과 ‘현재 구독 유지’도 적합한 결과다. 제휴 전환을 위해 불필요한 새 도구나 장기 결제를 추천하지 않는다.

**검증 — 검색 정확도와 고객의 이해·실제 활용을 함께 본다.**

초기에는 입문자와 여러 도구를 사용하는 사람을 포함한 8명 내외의 사용성 테스트를 제안한다. 과제는 서비스 등록·상태 수정, 목적 검색과 이유 설명, 예시 작업 시작, 저장 후 다른 기기에서 다시 찾기, 맞지 않는 추천 수정이다. 첫 내부 목표의 예시는 8명 중 6명 이상의 주요 과제 독립 수행이며, 작은 표본을 시장 수요나 전체 성공률로 일반화하지 않는다.

검색 품질은 대표 한국어 요청 30~50개로 기준 사례를 만든다. 이 숫자는 시작안이다. 서비스명·별칭, 기능명, 긴 목적 문장, 무료/추가 결제의 차이, 한국어·파일·연동 제약, 미확인 요금제, 기존 도구로 가능한 작업, 결과 없음, 상충 조건을 포함한다. 조건별 정답 근거와 관련성 기준을 기록해 방식 변경 전후 같은 사례로 비교한다.

| 검증 대상 | 확인 방법 | 출시·개선에 반영할 기준 |
|---|---|---|
| 개인 페이지의 유용성 | 서비스 추가 후 다시 찾아 상태·목적을 설명하고 갱신하는지 | 필수 입력과 정리 동선을 줄임 |
| 비용 이해·정확성 | 월 환산과 실제 결제를 구분하고 기간별 합계·연 결제·환율·중복·미입력을 대조 | 잘못된 합계와 미확인을 0원 처리하는 문제 수정 |
| 절약 제안의 타당성 | 같은 기간의 비용·필수 기능·할인 자격·전환 비용·적용 시점 대조 | 조건 미충족 추천과 중복 절감 집계 금지 |
| 검색 관련성 | 상위 3개 안에 과제에 맞고 조건이 확인된 방법이 있는 요청 비율 | 무응답·엉뚱한 후보·표현 미이해를 분리해 개선 |
| 필수 조건 준수 | 적합하다고 표시한 결과의 무료·언어·플랜·연동 조건을 대조 | 출시 평가 사례에서 알려진 필수 조건 위반 0건을 목표; 미확인도 충족으로 표시 금지 |
| 추천 설명 | 고객이 추천 이유와 제한을 자신의 말로 설명하는지, 표시 이유가 실제 근거와 일치하는지 | 이해하지 못한 표현과 부정확한 이유 수정 |
| 기록·공개 범위 | 계정 간 접근 분리, 다른 기기 재조회, 실패 복구·삭제를 확인 | 다른 고객의 기록 노출과 거짓 저장 성공은 출시 차단 |
| 유익·재미 | 실제 업무에 적용한 결과와 다시 해보고 싶은 이유를 각각 질문 | 흥미와 실용을 구분해 콘텐츠·추천 개선 |
| 재사용·운영 | 저장 후 1~7일 재조회·갱신, 정보 갱신 시간, 검색 실패·제보 처리량 | 반복 이용 이유와 유지 가능한 범위 확인 |

검색 관련성 비율은 답이 존재하는 평가 요청을 분모로 하고, 답이 없는 사례는 적절한 무결과·확인 필요 안내로 별도 평가한다. 출시 전 평가에서 오류가 없다는 것은 모든 실제 검색의 정확도를 보장하는 뜻이 아니다. 클릭률만으로 추천을 최적화하거나, 외부 사이트 이동·복사를 성공한 사용으로 집계하지 않는다.

재사용은 7일 관찰이 끝난 기록 사용자를 분모로 삼고 미시도·미응답을 구분한다. 운영 성과는 ‘최근 7일에 실제 작업에 활용했고 구체적인 도움이 있었다고 응답한 고유 사용자 수’를 중심 후보로 둔다. 자기보고임을 밝히고 첫 출시 전에는 사용성·조건 정확성·기록 복구를 우선 검증한다.

**후속 화면 명세는 개인 페이지·구독 비용, 목적 검색 결과, 기능·요금제 비교 순서로 구체화한다.** 각 화면의 고객 목표·대표 행동·필요 정보·성공 상태·빈 상태·실패 복구·다음 행동을 같은 양식으로 작성한다. 개인 페이지를 이용의 기반으로, 검색·연관 추천·비용 비교를 고객이 더 잘 활용하고 지출을 결정하도록 돕는 핵심 기능으로 정한다.
