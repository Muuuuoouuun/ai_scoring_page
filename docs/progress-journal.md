## 2026-08-25 — 진단 및 P0 작업

### 먼저 정정: 실행 환경 이슈는 더 이상 사실이 아님
이 문서와 `next-step-roadmap.md`, `connection-speed-check.md`는
"npm 레지스트리 403 때문에 실행·검증 불가"를 전제로 쓰여 있었습니다.
재확인 결과 **설치·빌드·개발서버·5개 페이지 렌더가 모두 정상**입니다.
로드맵의 리스크 항목(사내 npm proxy 구성 등)은 그 전제 위에 세워졌으므로 다시 판단해야 합니다.

| 항목 | 진단 시점 상태 |
| --- | --- |

## P0 작업 내용 (완료)

### 1) 파생 점수 폐기 → 근거가 붙은 실제 입력값으로 전환
- `lib/insights.ts`의 `deriveScoreBreakdown` / `deriveComparisons` / `derivePatchNotes` /
  `deriveWorkPlaybook`을 **전부 삭제**했습니다. 이제 이 파일은 평균만 계산합니다.
- `ScoreFacet` 타입을 도입해 **모든 점수에 근거(reason)를 필수**로 만들었습니다.
  근거는 화면에도 그대로 노출됩니다. 근거를 숨기면 같은 문제가 형태만 바꿔 남습니다.
- 점수 검증 스키마(`lib/validators.ts`)도 근거 없는 점수를 400으로 거부합니다.

**결과**
| 지표 | 이전 | 이후 |
| --- | --- | --- |
| 총점 폭 | 12점 (60~72) | 28점 (55~83) |
| 항목 점수 범위 | 사실상 2값씩 | 30~94 |
| 고유 가격 점수 | 2개 | 10개 |
| 고유 안정성 점수 | 2개 | 10개 |

### 2) 도구 10개 전부 실제 리뷰 작성
- `data/reviews.ts` 신설. 도구별 총평·점수 근거·비교·실무 가이드를 **모두 다르게** 작성했습니다.
- 도구를 6개로 줄이는 대신 10개를 유지하고 전부 채웠습니다. 데이터를 지우지 않는 편이 되돌리기 쉽습니다.
- `data/tools.ts`는 리뷰가 없는 도구가 있으면 **빌드 시점에 실패**합니다.
  조용히 빈 값으로 넘어가면 "내용 없는 리뷰"가 다시 생기기 때문입니다.

> ⚠️ **검수 필요**: 리뷰 본문은 편집 시드입니다. 공개 전 담당 에디터의 검토·서명이 필요합니다.

### 3) 패치 이력을 정직하게
- 확인되지 않은 변경 이력은 **지어내지 않고 빈 배열**로 두었습니다.
  현재 4개 도구(Notion·Figma·Slack·Airtable)만 항목이 있고, 나머지 6개는
  화면에 "아직 확인된 변경 이력이 없습니다"로 노출됩니다.
- 영향도(높음/보통/낮음) 배지를 추가했습니다.

### 4) 인증 없는 공개 입력 폼 정리
- 패치노트 입력 폼을 **제거**했습니다. "회사 담당자가 남길 수 있습니다"라고 안내했지만
  실제로는 인증이 없었고 저장도 작성자 브라우저에만 됐습니다.
  검수 워크플로와 권한 모델이 준비되기 전까지는 열지 않습니다.
- 커뮤니티 페이지의 지어낸 지표와 가상 사용자를 제거하고 준비 중 상태로 바꿨습니다.
- 리뷰 작성 폼에 "이 브라우저에만 저장됩니다" 경고를 명시했습니다.

### 5) 비교표 레이아웃 수정
- 사이드바 → **본문 중앙**으로 이동.
- 반응형 기준을 **뷰포트에서 컨테이너로** 바꿨습니다(`auto-fit`).
  이전에는 `max-width:720px` 뷰포트 미디어쿼리라 380px 사이드바에서는 끝내 걸리지 않았습니다.

### 6) 회귀 방지 테스트
`tests/review-integrity.test.ts` 신설. 아래가 깨지면 실패합니다.
- 총평·비교 문장·가이드 제목·패치 제목이 도구 간에 공유되는 경우
- 점수 근거가 비어 있거나 도구 간에 재사용되는 경우
- 총점 폭이 20점 이하로 좁아지는 경우
- 가격·안정성 점수가 소수의 값으로 고정되는 경우

기존 검색 테스트는 `query`가 없으면 전체를 반환하는 필터 버그 때문에
통과해도 아무것도 증명하지 못합니다. 이건 P2에서 필터와 함께 고칩니다.

## 이어서 개발한 내용 (Phase 1 시작)

### 1) 서버 저장형 리뷰 API
- `GET /api/tool/:id/reviews`
- `POST /api/tool/:id/reviews`
- 기존 localStorage 리뷰 저장을 서버 API 기반 저장/조회 흐름으로 전환

### 2) 서버 저장형 패치/장애 기록 API
- `GET /api/tool/:id/patches`
- `POST /api/tool/:id/patches`
- 관리자 ID 기반 최소 권한 체크 추가
- 영향도(High/Medium/Low)와 장애 여부를 기록 가능하게 확장

### 3) 감사 로그 최소 단위
- 리뷰/패치 생성 시 audit log 기록
- `GET /api/audit?toolId=`로 관리자 조회 가능

### 4) DB 스키마 확장
- review_scores, user_reviews, patch_updates, capability_matrix, audit_logs 테이블 초안 추가
- `DATABASE_URL`이 있으면 PostgreSQL 저장소를 사용하고, 없으면 로컬 개발/테스트용 in-memory store로 동작
- API 첫 쓰기 시 정적 툴 데이터를 `tools` 테이블에 자동 seed
