## P0 작업 내용 (완료)

### 1) 파생 점수 폐기 → 근거가 붙은 실제 입력값으로 전환
- `lib/insights.ts`의 `deriveScoreBreakdown` / `deriveComparisons` / `derivePatchNotes` /
  `deriveWorkPlaybook`을 **전부 삭제**했습니다. 이제 이 파일은 평균만 계산합니다.
- `ScoreFacet` 타입을 도입해 **모든 점수에 근거(reason)를 필수**로 만들었습니다.
  근거는 화면에도 그대로 노출됩니다. 근거를 숨기면 같은 문제가 형태만 바꿔 남습니다.
- 점수 검증 스키마(`lib/validators.ts`)도 근거 없는 점수를 400으로 거부합니다.

**결과**
| 지표 | 이전 | 이후 |
| --- | --- | --- |
| 총점 폭 | 12점 (60~72) | 28점 (55~83) |
| 항목 점수 범위 | 사실상 2값씩 | 30~94 |
| 고유 가격 점수 | 2개 | 10개 |
| 고유 안정성 점수 | 2개 | 10개 |

### 2) 도구 10개 전부 실제 리뷰 작성
- `data/reviews.ts` 신설. 도구별 총평·점수 근거·비교·실무 가이드를 **모두 다르게** 작성했습니다.
- 도구를 6개로 줄이는 대신 10개를 유지하고 전부 채웠습니다. 데이터를 지우지 않는 편이 되돌리기 쉽습니다.
- `data/tools.ts`는 리뷰가 없는 도구가 있으면 **빌드 시점에 실패**합니다.
  조용히 빈 값으로 넘어가면 "내용 없는 리뷰"가 다시 생기기 때문입니다.

> ⚠️ **검수 필요**: 리뷰 본문은 편집 시드입니다. 공개 전 담당 에디터의 검토·서명이 필요합니다.

### 3) 패치 이력을 정직하게
- 확인되지 않은 변경 이력은 **지어내지 않고 빈 배열**로 두었습니다.
  현재 4개 도구(Notion·Figma·Slack·Airtable)만 항목이 있고, 나머지 6개는
  화면에 "아직 확인된 변경 이력이 없습니다"로 노출됩니다.
- 영향도(높음/보통/낮음) 배지를 추가했습니다.

### 4) 인증 없는 공개 입력 폼 정리
- 패치노트 입력 폼을 **제거**했습니다. "회사 담당자가 남길 수 있습니다"라고 안내했지만
  실제로는 인증이 없었고 저장도 작성자 브라우저에만 됐습니다.
  검수 워크플로와 권한 모델이 준비되기 전까지는 열지 않습니다.
- 커뮤니티 페이지의 지어낸 지표와 가상 사용자를 제거하고 준비 중 상태로 바꿨습니다.
- 리뷰 작성 폼에 "이 브라우저에만 저장됩니다" 경고를 명시했습니다.

### 5) 비교표 레이아웃 수정
- 사이드바 → **본문 중앙**으로 이동.
- 반응형 기준을 **뷰포트에서 컨테이너로** 바꿨습니다(`auto-fit`).
  이전에는 `max-width:720px` 뷰포트 미디어쿼리라 380px 사이드바에서는 끝내 걸리지 않았습니다.

### 6) 회귀 방지 테스트
`tests/review-integrity.test.ts` 신설. 아래가 깨지면 실패합니다.
- 총평·비교 문장·가이드 제목·패치 제목이 도구 간에 공유되는 경우
- 점수 근거가 비어 있거나 도구 간에 재사용되는 경우
- 총점 폭이 20점 이하로 좁아지는 경우
- 가격·안정성 점수가 소수의 값으로 고정되는 경우

기존 검색 테스트는 `query`가 없으면 전체를 반환하는 필터 버그 때문에
통과해도 아무것도 증명하지 못합니다. 이건 P2에서 필터와 함께 고칩니다.

## 2026-08-25 — Postgres 어댑터

메모리 저장소만 있어서 서버를 재시작하면 사용자 기여가 전부 사라지던 상태를 해결했습니다.

### 구현
- `lib/community/postgres-store.ts` — 저장소 인터페이스의 Postgres 구현
- `db/community.sql` — 스키마. 여러 번 실행해도 안전합니다(`npm run db:setup`)
- `lib/community/index.ts` — `DATABASE_URL`이 있으면 Postgres, 없으면 메모리.
  화면과 API는 어느 쪽이 붙었는지 모릅니다.

### 계약 테스트가 실제 버그를 잡았습니다
`tests/community-store.test.ts`는 **두 구현에 같은 테스트를 돌립니다.**
그 덕분에 메모리 어댑터에 반박 근거 20자 규칙이 **없다는 것**을 발견했습니다.
API 검증(zod)과 DB 제약에는 있었지만 메모리 어댑터에는 없어서,
개발에서 통과한 데이터가 운영에서 거부되는 상태였습니다.
규칙을 `MIN_DISSENT_REASON` 상수 하나로 모으고 세 계층이 공유하게 했습니다.

### 소유 증명을 handle에서 token_hash로
이전에는 `touchDecision`이 표시 이름(handle)으로 본인 여부를 판단했습니다.
handle은 화면에 노출되는 값이라 소유 증명에 쓰면 안 됩니다.
토큰 해시로 바꾸고, "같은 표시 이름을 흉내내도 갱신하지 못한다"를 계약 테스트에 넣었습니다.

### 검증
실제 PostgreSQL 16을 띄워 확인했습니다.
- 계약 테스트 28개 통과(메모리 14 + Postgres 14, 동일한 테스트)
- HTTP 흐름: 반박 등록 → 쿠키 발급 → 집계 조회 → DB 적재 확인
- 권한: 본인 재확인 200, 타인 403
- 고장 제보는 `pending`으로 들어가고 공개 목록에 뜨지 않음
- **서버 재시작 후에도 기여·갱신된 상태·쿠키 신원이 모두 유지됨**

### 운영 시 주의
`DATABASE_URL`과 `AIS_AUTHOR_SECRET`이 없으면 프로덕션에서 경고를 남깁니다.
후자가 없으면 재시작마다 기여자 신원이 끊겨 본인 기록을 수정할 수 없게 됩니다.
`.env.example` 참조.

테스트 31 → 45개(DB 포함 시 59개).

### 검증

타입체크·테스트 45개·프로덕션 빌드 통과. 6개 화면 × 2 뷰포트(1280 / 390)를
실제 브라우저로 측정했습니다.

- 가로 오버플로 **전 화면 0px** (비교표의 가로 스크롤은 `.compare-scroll` 안에서만 발생)
- 화면마다 `h1` 정확히 1개
- Epilogue·IBM Plex Sans KR 두 웹폰트 모두 실제 적용 확인(`document.fonts.check`)
- 콘솔 에러 0

검증 중에 한 번 "모바일 홈에 138px 오버플로가 생기고 콘텐츠가 사라졌다"는 결과가
나왔는데, 원인은 코드가 아니라 **이전 빌드의 서버가 포트를 잡고 있어서**
지워진 CSS 청크를 참조하고 있었던 것이었습니다(스타일 없는 페이지). 서버를 실제로
교체한 뒤 재측정해 정상 확인했습니다.
