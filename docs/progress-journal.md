## 2026-08-25 — 진단 및 P0 작업

### 먼저 정정: 실행 환경 이슈는 더 이상 사실이 아님
이 문서와 `next-step-roadmap.md`, `connection-speed-check.md`는
"npm 레지스트리 403 때문에 실행·검증 불가"를 전제로 쓰여 있었습니다.
재확인 결과 **설치·빌드·개발서버·5개 페이지 렌더가 모두 정상**입니다.
로드맵의 리스크 항목(사내 npm proxy 구성 등)은 그 전제 위에 세워졌으므로 다시 판단해야 합니다.

## P0 작업 내용 (완료)

### 1) 파생 점수 폐기 → 근거가 붙은 실제 입력값으로 전환
- `lib/insights.ts`의 `deriveScoreBreakdown` / `deriveComparisons` / `derivePatchNotes` /
  `deriveWorkPlaybook`을 **전부 삭제**했습니다. 이제 이 파일은 평균만 계산합니다.
- `ScoreFacet` 타입을 도입해 **모든 점수에 근거(reason)를 필수**로 만들었습니다.
  근거는 화면에도 그대로 노출됩니다. 근거를 숨기면 같은 문제가 형태만 바꿔 남습니다.
- 점수 검증 스키마(`lib/validators.ts`)도 근거 없는 점수를 400으로 거부합니다.

**결과**
| 지표 | 이전 | 이후 |
| --- | --- | --- |
| 총점 폭 | 12점 (60~72) | 28점 (55~83) |
| 항목 점수 범위 | 사실상 2값씩 | 30~94 |
| 고유 가격 점수 | 2개 | 10개 |
| 고유 안정성 점수 | 2개 | 10개 |

### 2) 도구 10개 전부 실제 리뷰 작성
- `data/reviews.ts` 신설. 도구별 총평·점수 근거·비교·실무 가이드를 **모두 다르게** 작성했습니다.
- 도구를 6개로 줄이는 대신 10개를 유지하고 전부 채웠습니다. 데이터를 지우지 않는 편이 되돌리기 쉽습니다.
- `data/tools.ts`는 리뷰가 없는 도구가 있으면 **빌드 시점에 실패**합니다.
  조용히 빈 값으로 넘어가면 "내용 없는 리뷰"가 다시 생기기 때문입니다.

> ⚠️ **검수 필요**: 리뷰 본문은 편집 시드입니다. 공개 전 담당 에디터의 검토·서명이 필요합니다.

### 3) 패치 이력을 정직하게
- 확인되지 않은 변경 이력은 **지어내지 않고 빈 배열**로 두었습니다.
  현재 4개 도구(Notion·Figma·Slack·Airtable)만 항목이 있고, 나머지 6개는
  화면에 "아직 확인된 변경 이력이 없습니다"로 노출됩니다.
- 영향도(높음/보통/낮음) 배지를 추가했습니다.

### 4) 인증 없는 공개 입력 폼 정리
- 패치노트 입력 폼을 **제거**했습니다. "회사 담당자가 남길 수 있습니다"라고 안내했지만
  실제로는 인증이 없었고 저장도 작성자 브라우저에만 됐습니다.
  검수 워크플로와 권한 모델이 준비되기 전까지는 열지 않습니다.
- 커뮤니티 페이지의 지어낸 지표와 가상 사용자를 제거하고 준비 중 상태로 바꿨습니다.
- 리뷰 작성 폼에 "이 브라우저에만 저장됩니다" 경고를 명시했습니다.

### 5) 비교표 레이아웃 수정
- 사이드바 → **본문 중앙**으로 이동.
- 반응형 기준을 **뷰포트에서 컨테이너로** 바꿨습니다(`auto-fit`).
  이전에는 `max-width:720px` 뷰포트 미디어쿼리라 380px 사이드바에서는 끝내 걸리지 않았습니다.

### 6) 회귀 방지 테스트
`tests/review-integrity.test.ts` 신설. 아래가 깨지면 실패합니다.
- 총평·비교 문장·가이드 제목·패치 제목이 도구 간에 공유되는 경우
- 점수 근거가 비어 있거나 도구 간에 재사용되는 경우
- 총점 폭이 20점 이하로 좁아지는 경우
- 가격·안정성 점수가 소수의 값으로 고정되는 경우

기존 검색 테스트는 `query`가 없으면 전체를 반환하는 필터 버그 때문에
통과해도 아무것도 증명하지 못합니다. 이건 P2에서 필터와 함께 고칩니다.

### 2) 점수 시스템 (`lib/scoring.ts`)
- 편집 점수 = 5축 가중 평균 (기능 완성도 25%, UI/UX 15%, 에러/안정성 25%, 쾌적도 15%, 가격 합리성 20%).
- 외부 평가 점수 = 외부 리뷰 사이트 평점을 100점으로 정규화한 뒤 사이트별 신뢰 가중치(G2·Capterra·TrustRadius 1.0, Product Hunt·앱스토어 0.8, Trustpilot 0.5)로 가중 평균. 설문 재인용·리뷰 건수처럼 점수가 아닌 항목은 자동 제외.
- 종합 점수 = 편집 70% + 외부 30% (외부 평가가 없으면 편집 100%). 등급: 85+ 강력 추천, 75+ 추천, 65+ 조건부 추천, 그 외 신중 검토. 전체/카테고리 순위를 함께 표시.

### 3) 별점 시스템
- 편집팀 별점(종합 점수/20)과 커뮤니티 별점(사용자 리뷰 평균, 1~5점 분포 히스토그램), 외부 사이트 별점을 리뷰 페이지 "별점 요약" 카드에 표시.
- 리뷰 저장을 `lib/reviews.ts`로 분리하고 커스텀 이벤트로 동기화해, 리뷰를 등록하면 별점 요약이 즉시 갱신됩니다(현재는 브라우저 로컬 저장).
- 검색/홈/추천 카드에 별점·등급·종합 점수를 노출.

### 4) 비교 시스템
- `/compare` 페이지: 최대 3개 도구를 종합 점수·5축·임팩트 4축·판단 배지·기능 지원 매트릭스(지원/부분 지원/미지원 10개 항목)·가격·핵심 기능·외부 평가·최선/최악 시나리오로 나란히 비교. 축별 선두를 강조하고 "차이 요약"을 자동 생성.
- 모든 카드와 리뷰 헤더에 "비교함 담기" 버튼, 하단 고정 비교함 트레이 추가.

### 5) 추천 시스템 (`lib/recommend.ts`)
- `/recommend` 페이지: 직군(7종), 팀 규모(4종), 우선순위(최대 2개), 제약 조건(락인 회피·한국어 필수·무료 플랜 필수)을 고르면 적합도(0~100)를 계산하고 추천 이유와 주의할 점을 함께 보여줍니다.
- 적합도 = 종합 점수(최대 35) + 우선순위 지표(최대 35) + 직군 적합(최대 15) + 팀 규모 적합(최대 10) ± 제약 조건 가점/감점. 서비스 종료 도구는 제외.
- 리뷰 페이지의 "함께 비교할 도구"를 유사도(공유 문제 상황, 카테고리, 대안 관계, 임팩트 코사인 유사도, 직군 겹침) 기반으로 교체.

각 사이트마다 한 줄 정체성, 실무에서 언제 여는지, 다른 곳 대비 강점, 주의할 점, 가격 조건, 한국어 사용 편의, 비슷한 사이트를 적었습니다. 특히 **라이선스 주의점을 구체적으로** 남겼습니다. 예를 들어 눈누는 폰트마다 제작사 라이선스가 다르다는 점, unDraw는 AI 학습 사용이 금지된다는 점, Unsplash는 저작권 분쟁 배상 조항이 없다는 점, Google Fonts는 OFL의 Reserved Font Name 제약이 있다는 점을 적었습니다.

화면에는 키워드 검색, 그룹 필터, "무료/부분 무료만", "한국어로 쓰기 편한 곳만" 필터를 붙였고 `/api/resources` 엔드포인트도 함께 열었습니다.

### 참고: "enhance.net"
요청에 있던 "enhance.net"은 실제로 존재하는 레퍼런스 사이트가 아닙니다. 도메인 형태로 보아 **behance.net(비핸스)** 을 가리킨 것으로 보이며, 비핸스는 레퍼런스 그룹에 이미 포함했습니다. 이미지 보정 도구를 뜻한 것이라면 **Let's Enhance(letsenhance.io)** 가 가장 가까워 이미지 그룹에 함께 넣었습니다.
