**AI Score / AIs — 고객 경험 중심 디벨롭 기획서 v0.2**

AI·SaaS 정보 탐색·평가·소식·커뮤니티와 개인 관리의 비중을 재정리한 최신 제안은 [통합 기획서 v0.6](/Users/bigmac_moon/dev/ai_score/docs/2026-09-12-product-plan-v0.6.md)이다. 정보 경험은 개인 관리와 최소 동등한 비중을 갖고 기본 홈에서 먼저 드러낸다. 이 문서는 이전 논의 기록이며, 충돌하는 전체 방향·홈·출시·성과 기준은 v0.6을 따른다.

작성일: 2026-09-11. 서비스명은 가칭이다. 이 문서는 앞선 정체성 기획 v0.1을 고객 경험·사용 편의·유익·재미 중심으로 발전시킨 당시의 제품 방향 제안이다. 타깃·운영 규모·수치는 검증 전 가정이며, 구현 완료를 의미하지 않는다.

**서비스의 정체성은 ‘나에게 맞는 AI·SaaS를 발견하고, 쉽게 써보며, 함께 더 잘 활용하는 서비스’다.** 선택을 돕는 정보와 실사용 커뮤니티를 연결한다. 고객이 얻을 결과는 나에게 맞는 도구를 이해하고, 작은 작업을 완성하고, 다음에도 활용할 수 있게 되는 것이다.

> 나에게 맞는 AI를 발견하고, 쉽게 시작하세요.
>
> 어떤 도구가 맞는지부터 어떻게 써야 하는지까지. 내 상황에 맞는 비교와 다른 사람의 경험을 함께 살펴보세요.

기존 기획의 비교·평가·사용 기록·변화 추적을 유지하면서, 첫 사용 안내와 발견의 재미를 제품의 중심에 추가한다. 탐색하는 고객과 당장 해결할 일이 있는 고객 모두 편하게 시작할 수 있게 한다.

| 이전 기획에서 발전시킬 지점 | v0.2에서 정하는 방향 | 고객에게 생기는 변화 |
|---|---|---|
| 적합한 도구를 비교해 선택 | 선택 후 작은 작업까지 안내 | ‘좋아 보인다’에서 ‘내가 해봤다’로 이어짐 |
| 문제·제약·탈락 조건의 강조 | 가능한 일, 시작 방법, 한계를 함께 설명 | 입문자가 부담 없이 이해함 |
| 도구 정보와 점수 중심 상세 | 내 상황에서의 쓰임과 다음 행동을 먼저 제시 | 긴 설명을 읽기 전에도 판단 가능 |
| 공개 기여 중심 기록 | 개인 기록부터 시작하고 공개는 선택 | 부담을 낮추면서 경험을 축적 |
| 업데이트를 확인하는 재방문 | 진행 중인 작업·새 활용법·관련 변화로 재방문 | 새 도구를 사지 않아도 계속 쓸 이유가 생김 |

**우선순위는 고객 사용과 친절함에 가장 큰 비중을 둔다.** 아래 비중은 내부 기능 선정과 디자인 검토에 쓰는 제안치다. 도구 평가 점수나 고객 조사 결과와 혼용하지 않는다.

| 판단 기준 | 가중치 | 기능을 검토할 때 묻는 것 |
|---|---|---|
| 사용 편의·친절함 | 40% | 처음 온 사람이 이해하고, 막혀도 스스로 다음 행동을 할 수 있는가? |
| 실제 유익 | 30% | 선택·작업·비용·정보 확인 중 어떤 수고를 줄여주는가? |
| 재미·다시 찾고 싶은 마음 | 20% | 새로운 발견, 작은 성취, 나다운 정리, 사람들과의 교류가 있는가? |
| 확장성·운영 지속성 | 10% | 같은 정보와 구조로 다음 기능을 만들고 계속 관리할 수 있는가? |

출처·평가 근거의 정확성, 공개 범위에 대한 동의, 기본 접근성은 가중치와 별도로 충족해야 할 조건이다. 점수가 높은 기능도 이 조건을 충족하지 못하면 출시하지 않는다. 반복 확인이 어려운 기능은 정보 범위를 먼저 줄인다.

**초기 핵심 고객은 업무에 AI를 조금씩 쓰기 시작한 한국어 실무자로 가정한다.** 리서치·보고서·콘텐츠 기획을 하는 개인과 작은 팀의 구성원을 먼저 다룬다. 직무보다 ‘지금 무엇이 필요한가’로 고객 경험을 나눈다. 같은 사람도 방문할 때마다 다른 상태일 수 있다.

| 고객의 방문 상태 | 고객의 말 | 필요한 경험 | 첫 성공의 기준 |
|---|---|---|---|
| 가볍게 둘러보는 사람 | ‘요즘 AI로 뭘 할 수 있어?’ | 결과 예시가 있는 발견 카드 | 내 상황에 써볼 만한 활용법 하나를 찾음 |
| 해결할 일이 있는 사람 | ‘이 자료를 보고서로 정리하고 싶어’ | 쉬운 조건 선택, 소수 후보 비교, 시작 안내 | 후보를 고른 이유와 첫 작업을 설명할 수 있음 |
| 이미 도구를 쓰는 사람 | ‘지금 쓰는 걸 더 잘 쓰고 싶어’ | 기존 도구 활용법, 저장한 작업, 관련 변화 | 새로운 구독 없이 활용 범위를 넓히거나 선택을 재검토함 |

팀 관리자·전문 개발자·기업 구매 담당자는 후속 고객 후보로 둔다. 초기 도구의 깊이는 리서치·문서·콘텐츠 기획에 집중하되, 발견 피드에는 이 업무들과 연결되는 AI·SaaS 소식과 행사를 선별할 수 있다.

**서비스 구조는 고객이 하는 네 가지 행동에 맞춘다.** 상단 공통 검색에서 도구 이름·하고 싶은 일·활용법을 찾을 수 있고, 검색 결과에는 유형을 표시한다. 모바일에서도 같은 메뉴 이름을 유지한다.

| 주요 메뉴 | 하위 구성 | 고객의 대표 행동 |
|---|---|---|
| 발견 | 오늘의 발견, 짧게 따라하기, 새 소식·업데이트·행사 | 흥미로운 가능성을 보고 저장하거나 시작 |
| 도구 찾기 | 업무별 탐색, 조건 선택, 도구 상세, 나란히 비교 | 내 조건에 맞는 도구를 이해하고 선택 |
| 경험 나누기 | 사용 후기, 선택 질문, 활용 방법·도구 조합 | 비슷한 사람의 경험을 보고 짧게 참여 |
| 내 도구함 | 관심·사용 도구, 저장한 활용법, 비교·선택 기록, 내 도구 소식 | 이전 활동을 이어가고 사용 결과를 정리 |

비교는 ‘도구 찾기’ 안의 행동이며, 뉴스·업데이트·행사는 ‘발견’ 안의 콘텐츠 유형이다. 도움말·평가 기준·문의는 어느 화면에서든 익숙한 위치에서 찾게 한다. ‘내 도구함’의 개인 기록은 기본 비공개다.

내부 구조는 고객 경험, 연결된 정보, 운영의 세 층으로 둔다. 고객 경험 층은 탐색·선택·시도·저장을 담당한다. 정보 층은 도구·업무·활용법·근거·변경·경험을 연결한다. 운영 층은 검수·갱신·오류 수정·신고 처리를 담당한다. 고객에게는 필요한 출처와 확인 상태를 보여주고, 구현 파일이나 테스트 이름은 제품 설명에 넣지 않는다.

**첫 화면에는 두 개의 입구를 둔다.** ‘하고 싶은 일로 찾기’와 ‘가볍게 둘러보기’다. 어떤 도구를 찾을지 모르는 사람도 시작할 수 있어야 한다.

새 방문자는 할 수 있는 일의 예시, 짧은 결과 미리보기, 대표 비교를 먼저 본다. 재방문자는 진행하던 비교와 저장한 활용법을 이어서 보고, 사용 중인 도구의 관련 소식을 확인한다. 메뉴 위치는 유지하며 콘텐츠의 우선순위만 조정한다. 저장 이력이 없는 방문자는 일반 발견 화면을 이용한다. 비회원도 같은 브라우저에 저장한 기록을 이어서 볼 수 있으며, 개인화의 이유는 필요한 곳에 ‘저장한 문서 작업과 관련된 내용’처럼 설명한다.

첫 방문의 체감 목표는 ‘여기서 무엇을 할 수 있는지 이해 → 내 상황에 맞는 예시 발견 → 다음 행동 하나 선택’이다. 첫 10초의 이해와 수 분 안의 첫 후보 선택을 사용자 테스트에서 관찰하되, 외부 도구의 가입·결제·처리 시간을 포함한 완료 시간을 보장하지 않는다.

**핵심 기능 1 — 오늘의 발견은 흥미를 사용으로 연결한다.** 카드 한 장에 할 수 있는 일, 결과 예시, 어울리는 상황, 시작 조건을 담는다. 도구의 이름보다 고객이 얻는 결과가 먼저 눈에 들어오게 한다.

예시 카드는 ‘긴 회의 메모에서 다음 할 일만 정리하기’, ‘조사 자료를 한 장 보고서로 만들기’, ‘하나의 글에서 여러 콘텐츠 기획 뽑기’다. 실제 결과 이미지는 제작 조건을 함께 표시한다. 뉴스 카드에는 변화의 의미, 대상, 출처·확인일을 넣고 관련 활용법이나 비교로 연결한다.

한 카드에는 ‘따라 해보기’, ‘비교 보기’, ‘저장’ 중 맥락에 맞는 대표 행동 하나를 두고 나머지는 보조로 제공한다. 초기에는 편집자가 구성한 소량의 카드로 시작한다. 관심 없는 주제는 숨기거나 관심 설정을 바꿀 수 있게 한다.

**핵심 기능 2 — 쉬운 도구 찾기는 고객의 표현을 그대로 받는다.** ‘리서치 자동화’ 같은 분류명과 함께 ‘자료를 찾아 보고서로 정리하고 싶어요’ 같은 생활·업무 언어를 사용한다.

안내형 탐색은 하고 싶은 일 → 중요한 조건 → 기존 도구의 세 묶음으로 시작한다. 필요한 정보만 묻고, 기존 도구와 예산이 정해지지 않았다면 건너뛸 수 있게 한다. 숙련자는 검색·필터로 바로 이동한다. 이전 답변과 선택은 뒤로 돌아가도 유지한다.

후보는 최대 3개를 먼저 제시하고, 각 후보에 추천 이유·확인할 제한·기존 도구와의 관계를 설명한다. 조건을 바꾸거나 후보를 더 보는 행동을 제공한다. 필수 조건에 맞는 후보가 없으면 그 이유와 변경 가능한 조건을 보여주며, 사용자의 동의 없이 조건을 완화하지 않는다. 대화형 AI는 입력 정리에 활용할 수 있지만 기본 탐색은 선택지와 검색만으로도 완료할 수 있게 한다.

**핵심 기능 3 — 도구 상세와 비교는 고객이 선택을 설명할 수 있게 돕는다.** 첫 화면에는 ‘이럴 때 좋아요’, ‘시작 전에 확인하세요’, ‘이렇게 써볼 수 있어요’를 배치한다. 상세 근거는 펼쳐서 볼 수 있게 하되, 비용·필수 제약·평가 상태는 쉽게 확인되게 한다.

| 기본 비교 항목 | 고객의 질문 |
|---|---|
| 잘 맞는 작업 | 내가 하려는 일이 가능한가? |
| 시작 난이도·준비 | 가입이나 설정은 얼마나 필요한가? |
| 비용·무료 범위 | 내가 써볼 범위에 결제가 필요한가? |
| 한국어·파일 처리 | 내 자료와 결과물에 맞는가? |
| 강점과 한계 | 무엇이 편하고, 무엇은 직접 해야 하는가? |

같은 업무와 조건에서 비교하고, 도구 하나만 고른 상태에서도 선택을 유지한 채 대안 추가를 안내한다. 모바일은 고객이 비교 중인 항목과 도구를 잃지 않게 구성한다. 항목별 점수는 평가일·요금제·과제·근거와 함께 상세 영역에 제공한다. 미확인을 0점으로 바꾸거나 검증되지 않은 개인 적합성 백분율을 표시하지 않는다.

결정은 ‘이 도구를 써볼래요’, ‘지금 쓰는 도구를 계속 쓸래요’, ‘나중에 다시 볼래요’로 표현한다. 고객이 이유를 남기면 이후 변경과 경험을 확인하는 맥락으로 활용한다.

**핵심 기능 4 — 짧게 따라하기는 첫 성공을 만든다.** 도구를 고른 뒤 작은 결과물을 완성하는 안내를 제공한다. 준비물 → 예시 자료 → 작업 순서 → 결과 확인 → 막혔을 때 도움으로 구성한다.

각 안내에는 가능한 요금제·가입 필요 여부, 예상 작업 시간, 예시 결과, 직접 확인할 부분을 표시한다. 따라 할 수 있는 예시 입력과 복사 가능한 프롬프트를 제공하고, 고객은 자신의 업무 자료를 올리지 않고도 먼저 연습할 수 있게 한다. 소요 시간은 어떤 조건에서 측정하거나 추정했는지 밝힌다.

초기에는 고객이 외부 도구에서 실행한다. 버튼은 ‘예시 복사’, ‘공식 도구에서 열기’처럼 실제 행동을 설명한다. 공식 사이트를 여는 것은 작업 완료로 집계하지 않는다. 돌아오면 ‘해봤어요 / 해보다 막혔어요 / 나중에 할게요’ 중 짧게 남길 수 있고, 막힌 경우 같은 안내 안에서 해결 방법이나 더 쉬운 대안을 제시한다.

**핵심 기능 5 — 내 도구함은 고객의 수고를 기억한다.** 관심 있음·시험 중·사용 중·사용 중단 상태와 사용 목적을 관리한다. 비교 후보, 선택 이유, 저장한 활용법, 사용 결과를 연결하고 다음 방문에 이어서 볼 수 있게 한다.

첫 버전의 비회원 기록은 브라우저에 보관하고 ‘이 브라우저에 저장’이라고 명시한다. 브라우저 데이터 삭제 시 기록이 사라질 수 있음을 처음 저장할 때 안내한다. 계정으로 여러 기기에서 보관하는 기능은 확장 단계로 두며, 브라우저 저장이 차단되거나 실패하면 현재 화면의 입력을 유지하고 복사·재시도를 제공한다. 저장 실패 시 성공했다고 표시하지 않는다. 기존 탭 안의 비교 목록과 장기 보관 기능은 구분한다.

사용 중인 도구의 기능·가격·제한이 바뀌면 적용 대상, 확인일, 고객이 확인할 행동을 알려준다. 발표 상태와 직접 테스트 여부는 각각 표시한다. 읽을 새 변경이 없으면 이전에 저장한 활용법을 이어서 보게 한다. 주제별·도구별 알림 설정과 끄기는 쉽게 찾을 수 있게 하며, 외부 알림은 별도 수신 동의를 받은 단계에서 도입한다.

**핵심 기능 6 — 경험 나누기는 가벼운 참여에서 시작한다.** 고객이 알고 있는 만큼 말할 수 있게 하고, 정교한 공개 평가는 충분한 맥락을 갖춰 받는다.

| 참여 깊이 | 고객의 행동 | 서비스에서 다루는 방식 |
|---|---|---|
| 짧은 반응 | ‘도움 됐어요’, ‘나도 해보고 싶어요’ | 콘텐츠 반응으로 표시하고 제품 성능 평점과 구분 |
| 개인 사용 기록 | ‘해봤어요’, ‘막혔어요’, ‘계속 쓸래요’ | 개인 도구함에 기록하며 공개를 강요하지 않음 |
| 공개 경험 | 작업, 사용 시점·플랜, 잘된 점·한계 | 같은 상황의 고객이 찾아볼 수 있는 후기 |
| 질문·다른 경험 | 선택 질문, ‘사용해보니 달랐어요’, 오류 제보 | 필요한 조건·근거를 안내하고 답변·수정 결과 연결 |

공개 기여를 작성할 때는 ‘어떤 일을 하셨나요?’, ‘어디까지 잘됐나요?’, ‘막힌 부분이 있었나요?’ 같은 질문을 제공한다. 필수 맥락과 선택 정보를 구분하고 예시를 붙인다. 상세 근거가 필요한 반론은 이유를 받되, 단순 반응에 같은 길이의 글을 요구하지 않는다. 실제 경험이 없는 반응을 실사용 후기로 집계하지 않는다.

다른 사람의 활용법을 자신의 도구함에 저장할 수 있게 하고, 실제로 따라 해본 뒤 결과를 추가할 수 있게 한다. 원 작성자를 표시하며 원본을 덮어쓰지 않는다. 공개 도구 모음과 공동 작업은 이후 확장한다.

**고객의 핵심 포인트는 사용·유익·재미를 같은 순간에 연결하는 것이다.** 아래는 조사로 입증된 심리가 아니라 검증할 경험 가설이다.

| 고객이 느끼는 어려움 | 쉽게 할 수 있는 사용 | 얻는 유익 | 느낄 수 있는 재미·감정 |
|---|---|---|---|
| ‘뭘 할 수 있는지 모르겠어’ | 결과 예시를 보고 한 가지 선택 | 활용 가능성을 빠르게 이해 | ‘이것도 되네’라는 발견 |
| ‘선택지가 너무 많아’ | 조건 몇 개로 후보를 좁혀 비교 | 탐색 수고와 결정 부담 감소 | 내 상황에 맞는 것을 찾는 만족 |
| ‘결제하고 안 쓸까 봐 걱정돼’ | 기존 도구 활용과 무료 범위를 먼저 확인 | 중복 결제·불필요한 학습 부담 감소 | 합리적으로 골랐다는 안도감 |
| ‘써봤는데 잘 안 돼’ | 예시로 작은 작업을 따라 하고 도움 확인 | 실제 시작과 막힘 해결 | 작은 결과를 직접 만든 성취감 |
| ‘소식이 너무 많아’ | 내 도구·관심 업무의 변화만 확인 | 읽을 양과 확인 수고 감소 | 필요한 새 활용법을 발견하는 흥미 |
| ‘후기를 쓰기 부담스러워’ | 짧은 기록 후 공개할 부분 선택 | 경험 정리와 다음 선택의 근거 확보 | 내 경험이 다른 사람에게 도움이 되는 보람 |

재미는 네 가지로 설계한다. 발견 카드의 ‘새 가능성’, 따라하기의 ‘작은 성취’, 내 도구함의 ‘나만의 정리’, 활용 경험을 주고받는 ‘교류’다. 추천한 도구의 수나 체류 시간만으로 재미를 판단하지 않고, 다시 해보고 싶은 작업과 저장·재사용의 이유를 확인한다.

| 재미를 만드는 장치 | 최소 형태 | 확장 시 확인할 신호 |
|---|---|---|
| 이번 주 한 가지 해보기 | 편집자가 고른 작은 작업 한 개와 결과 예시 | 직접 시도하거나 다음 작업을 찾는가 |
| 내 첫 도구 모음 | 저장한 도구에 사용 목적과 이름 붙이기 | 다음 방문에 다시 열어보는가 |
| 같은 작업의 다른 방법 | 두 도구·작업 방식의 결과 예시 비교 | 차이를 이해하고 자신의 방법을 선택하는가 |
| 함께 써본 경험 | 원본 활용법에 자신의 결과 연결 | 다른 고객이 재현하고 참고하는가 |

첫 출시에는 ‘이번 주 한 가지 해보기’를 따라하기 콘텐츠와 함께 운영한다. 공개 모음·결과 연결은 참여가 생긴 다음 확장한다. 기록에는 ‘보고서 작업을 한 번 해봤어요’처럼 확인된 행동을 보여주고, 근거 없이 능력이나 전문성을 인증하지 않는다.

**대표 고객 경험은 실제 행동과 감정의 변화로 설계한다.** 예시는 가상의 1인 마케터가 보고서 작업을 시작하는 상황이다.

| 시점 | 고객의 행동 | 서비스의 도움 | 고객에게 남는 것 |
|---|---|---|---|
| 발견 | ‘자료를 한 장 보고서로 만들기’ 카드를 연다 | 결과 예시와 필요한 조건을 먼저 보여줌 | 자신에게 쓸모 있는지 이해 |
| 이해 | 예산 미정, 기존 도구 사용 중을 선택한다 | 모르는 조건은 건너뛰고 설명을 제공 | 입력 부담 없이 후보 확보 |
| 선택 | 기존 도구와 대안 두 개를 비교한다 | 추천 이유·제약·시작 방법을 나란히 설명 | 기존 도구를 먼저 시험하기로 결정 |
| 첫 사용 | 예시 자료와 프롬프트로 한 작업을 해본다 | 준비물과 외부 도구 이동을 명확히 안내 | 작은 결과물과 사용 감각 |
| 막힘 해결 | 출처가 빠졌다고 표시한다 | 확인 순서와 수정 방법을 제시 | 스스로 수정할 수 있다는 자신감 |
| 정리 | 결과와 ‘계속 사용’을 저장한다 | 작성 중인 내용과 사용 목적을 유지 | 다음에도 꺼내 쓸 작업 기록 |
| 재방문 | 저장한 작업을 다시 열고 관련 변화를 본다 | 무엇이 달라졌고 무엇을 확인할지 설명 | 반복 작업에 활용 |
| 공유 | 도움이 됐던 부분만 공개한다 | 공개 범위를 미리 보여주고 취소 가능하게 함 | 부담 없는 참여와 교류 |

가볍게 둘러보는 고객은 카드 읽기 → 저장 → 나중에 따라하기까지로 끝내도 완결된 경험이다. 이미 도구를 쓰는 고객은 내 도구함 → 새 활용법·변경 → 기존 작업 재사용으로 바로 이동한다. 모든 고객에게 추천 설문과 공개 후기를 요구하지 않는다.

**친절함은 문구·입력·실패 복구·접근성의 구체적인 요구사항이다.** 같은 질문을 반복하지 않고, 필요한 정보를 묻는 이유를 설명하며, 뒤로 가도 입력을 보존한다. 이 설계는 GOV.UK의 질문 페이지 지침을 참고해 서비스에 적용한 제안이다. [GOV.UK Question pages](https://design-system.service.gov.uk/patterns/question-pages/).

| 상황 | 고객에게 보여줄 안내의 예 | 동작 요구사항 |
|---|---|---|
| 목적이 아직 없음 | ‘아직 정하지 않았나요? 활용 예시부터 둘러보세요.’ | 설문 없이 발견 화면 이용 |
| 용어가 어려움 | ‘연동: 지금 쓰는 다른 서비스와 연결하는 기능이에요.’ | 용어 옆에서 설명 열기, 키보드로도 접근 |
| 후보가 없음 | ‘선택한 조건을 모두 만족하는 도구는 아직 찾지 못했어요.’ | 어떤 조건이 제한하는지 표시하고 수정 허용 |
| 비교 후보가 하나 | ‘도구 하나를 더 담으면 나란히 비교할 수 있어요.’ | 기존 선택 유지, 관련 후보 제공 |
| 후기 없음 | ‘아직 사용 후기가 없어요. 확인된 기능과 활용 예시를 먼저 볼 수 있어요.’ | 다른 유용한 근거로 이어짐 |
| 직접 테스트 전 | ‘직접 테스트한 기록은 아직 없어요.’ | 공식 자료와 경험 근거를 구분 |
| 저장 실패 | ‘저장되지 않았어요. 작성한 내용은 이 화면에 남아 있어요.’ | 입력 보존, 재시도·복사 제공; 실제 보존 상태와 문구 일치 |
| 입력 누락 | ‘어떤 작업에 사용했는지 적어주세요. 예: 회의 메모 정리’ | 해당 필드에서 안내, 입력값 유지 |
| 오류 제보 접수 | ‘제보를 받았어요. 처리 상태는 여기서 확인할 수 있어요.’ | 접수 상태·후속 확인 경로 제공 |
| 저장 완료 | ‘이 브라우저의 내 도구함에 저장했어요.’ | 저장 위치와 취소·이동 행동 제공 |

고객의 실수처럼 보이는 표현을 피하고 무엇을 하면 되는지 구체적으로 설명한다. 오류 안내는 해당 입력과 연결하고 필요한 경우 상단에서도 위치를 찾게 한다. [GOV.UK Error message](https://design-system.service.gov.uk/components/error-message/).

도움말·문의의 위치는 일관되게 유지한다. 키보드 이동·보이는 포커스·텍스트 레이블을 제공하고, 점수나 상태는 색상 외에 글자로도 설명한다. 모바일에서 확대해도 읽을 수 있게 하며 움직임은 사용자의 설정을 존중한다. 이는 출시 검토 항목이며 현재 구현의 접근성 준수를 인증한 것은 아니다. [W3C Consistent Help](https://www.w3.org/WAI/WCAG22/Understanding/consistent-help.html).

**정보의 신뢰는 고객이 편하게 선택하기 위한 기반이다.** 첫 화면에는 결론·적용 조건·중요한 한계를, 자세히 보기에는 테스트 과제·날짜·출처·작성자를 제공한다. 독자가 필요에 맞춰 깊이를 선택할 수 있게 한다. 핵심 제한을 숨기거나 실제 사용을 확인하지 않은 후기를 실사용으로 표시하지 않는다.

도구의 공식 기능 정보, 운영진 테스트, 사용자 경험, 편집자의 해석을 구분한다. 도구가 변경되면 관련 평가와 따라하기 안내도 함께 점검한다. 단순 평균을 공개할 최소 표본 정책과 충분히 신뢰할 수 있는 표본은 다른 문제이므로, 표본 수와 시점·조건을 계속 보여준다. 광고·제휴는 별도 표시하며 일반 추천과 평가 점수에 영향을 주지 않게 한다.

**운영 구조는 작은 범위를 정확하게 유지하는 방식으로 시작한다.** 하나의 도구 정보를 다시 입력하지 않고 비교·활용법·업데이트·후기에 연결한다. 가격과 제한 조건이 바뀌면 영향을 받는 콘텐츠를 찾아 재확인할 수 있게 한다.

| 운영 묶음 | 운영자가 할 일 | 고객 경험에 필요한 기준 |
|---|---|---|
| 도구·비교 | 공식 기능·가격·제약 확인, 대표 작업 테스트 | 확인일과 근거, 적합한 상황을 설명 |
| 따라하기 | 예시 작업 재현, 플랜·가입 조건·막히는 지점 확인 | 안내를 따라 실제 결과물을 만들 수 있음 |
| 소식·행사 | 공식 원문 확인, 대상·일시·마감·변화의 의미 정리 | 참석·활용 여부를 판단할 정보가 있음 |
| 경험·질문 | 공개 기여 검토, 업체 관계·혜택 표시, 신고 처리 | 실제 경험과 질문을 안전하게 주고받음 |
| 도움·수정 | 반복 문의를 도움말에 반영, 제보 처리 상태 제공 | 다음 고객이 같은 곳에서 덜 막힘 |

핵심 도구의 가격·제한은 주 단위, 나머지 기본 정보는 월 단위 점검을 시작안으로 둔다. 중요한 변경이나 오류 제보가 있으면 추가 확인한다. 실제 운영 시간과 갱신 지연을 보고 주기와 범위를 조정한다. AI는 수집·분류·초안을 돕고 선택에 중요한 사실과 발행 상태는 운영자가 확인한다.
